# §14 困难集纪律

## 什么是困难集

验收集中长期不过、且常规优化拿它没办法的极端用例。
它们不是"再调调参就能过"的 case，而是**路线试金石**：
能过困难集的路线才有结构正确性；过不了的，迟早会在泛化上还债。

## 准入条件

WHEN 某用例满足以下全部 THEN 移入 `HARDSET.md` 独立管理：
- 已尝试 ≥2 种不同结构路线仍不过；
- 常规候选对它只有个位数改善或零改善；
- 它的失效机制与其他已过用例不同（不是同一家族）。

WHEN 用例只是"还没轮到优化" THEN 不许进困难集——
困难集不是待办清单，是路线判决席。

## 爆破纪律

1. 困难集用例**不参与**日常候选的评分，避免污染主线决策；
2. 每个困难用例独立建档：失效机制假设、已试路线、剩余未知；
3. 爆破时只允许**结构级**实验（换算法、换数据布局、换执行结构），
   禁止参数扫描——参数在主线已经证明无效；
4. 攻克一个困难用例后，立即检查主线其他用例是否连带改善
   （结构性方案的标志）；

## 换路线触发器

WHEN 连续 N 轮（建议 5）整体通过率只有个位数增长，
且困难集纹丝不动 THEN：
1. 停止一切参数级优化；
2. 写路线级复盘：当前路线在困难集上的失效机制是什么；
3. 强制引入一个**新算法家族**的候选（从 Specialist 研究或外部文献来，
   不许是当前路线的变体）；
4. 新路线先在困难集上验证，再谈全量。

这条规则专门对抗"白名单打补丁的局部最优"：
40→100→170 的渐近线爬得越顺，越要警惕——
顺利的局部最优是最贵的那种失败。
