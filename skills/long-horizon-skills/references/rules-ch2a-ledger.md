# §2 证据台账（L2 权威正文 · 上：台账机制）

> 本文件是 §2.1–§2.5.1 的权威正文。L1 索引只做指针；引用用编号，不复述。

## 2.1 数字进结论前带四要素

值 / 定义式 / 单位 / 出处；对比写清 A 相对 B（哪一臂是哪一臂）。

## 2.2 对比数字必须带主语

禁止裸写"+40%""快 3×"——没有主语，半年内会被读反。
必须写"A 相对 B 慢 40%"。
真实代价：同一份测量被引用时丢了主语，支持某方案的证据被当成反对它的证据，直接选错方向。

## 2.3 不得引用自己的旧总结作证据

引用历史数字前，回原始日志 / 原始 CSV / 源码重读一遍。摘要会漂移，原始数据不会。

## 2.4 量纲未核实的指标不算证据

三问：定义式是什么？单位是什么？**它可能超过 1 吗？**
（会 ⇒ 它不是比例，当百分比用必然出错。）

## 2.5 证据台账与 lint

**台账**：`CLAIMS.jsonl`，每条结论一行——
`id / 结论（一句话）/ 等级 / 原始证据路径 / derived_from / valid_from /`
`invalidated_at / invalidated_by / 记录人`。
等级手写只四种：`已实测` / `已被独立复核` / `未受攻击` / `INVALID`（与 §7.2 一致）。
"`未验证`"不是手写等级——是 lint 在原始证据路径 `test -f` 失败时**算出**的状态。
派生文档引用编号（`见 C-017`）不复述散文；等级只许降不许升。
条目永不删除，只失效（见下篇）。

真实代价：规程自己的失效目录曾把一次**从未执行**的实验写成"我方已实测"，
并附量化机制解释——**规程的第一个受害者是规程本身**。

**2.5.1 六条机械检查**（已脚本化为 `scripts/claims_lint.py`）：
① id 唯一合法；② 证据路径 `test -f`，不存在 ⇒ 自动降级`未验证`；
③ 派生文档不得升级等级、不得引用不存在的 id；④ 失效传递闭包
（`derived_from` 链上包含被推翻条目的必须也被标掉）；
⑤ **无支撑断言**（既无证据路径又无 `derived_from`）⇒ ERROR；
⑥ `invalidated_by` 悬空 ⇒ ERROR。

**重量控制**：`derived_from` 只对"没有原始证据路径"的条目必填；
有 `test -f` 的是 base fact，填 `—`。`valid_from` / `invalidated_at` /
`invalidated_by` 只在写入与失效时有值，平时留空。**不要回填历史台账**，
从下一个实验开始记——回填是负担的来源，不是纪律的来源。
