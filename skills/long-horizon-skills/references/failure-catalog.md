| id | 事实 | 代价 |

| B3 | 核验剔除规则用了无条件丢最大值，规则是"只丢 >3×median" | 写进协议的公式是错的，且更容易掩盖真实回归 |

## E. 装置失效（实验没在测它声称在测的东西）★

> 本类最隐蔽：**不产生异常数字**，产生"平坦"与"中性"，看起来像干净的否定结果。

| id | 事实 | 代价 |
|---|---|---|
| E1 | 探针插在无条件 `return` 之后 ⇒ 两臂跑同一份代码；产出完整结论+机制解释 | 假结论进状态日志/目录/复盘；撤回又花一整轮 |
| E2 | 预注册写"随机矩阵必有近零对角元"——测试生成器给对角加了偏移，判别式恒真 | 一轮实验 + 假前提 + 复核者背书（一次 grep 可避） |
| E3 | 观测编码把两种情形编成同一个整数，先后读出两个相反结论 | 两轮来回；能拿第一手观测量时别用编码 |
| E4 | 归档补丁写出 0 字节，源码按"已归档"记录却实际丢弃 | 没损失纯属侥幸（恰好 commit 过） |
| E5 | 最载重的对照测量没有 run 目录，数字只活在摘要里 | 结论不可复核 |
| E6 | 在从未 fetch 过该 MR 的仓里 `git cat-file`，断言"它已消失" | 差点让完全可行的复测被当成不可能 |
| E7 | 精度门脚本根本没执行（变量在子 shell 赋值），`grep -c FAILED` 对空日志得 0 ⇒ 报"满分通过" | 最尖锐的一种：读数在"没跑"与"全过"下完全相同 |

## H. 供给侧失效（问题出在别人给的判据/用例/验收脚本上）★

> （2026-09-14，另一个算子）七个最贵问题里**三个出在供给方**。

| id | 事实 | 代价 |
|---|---|---|
| H1 | 判据不可满足：`max_abs_error ≤ max(1e-2, 32·ULP)` 严了 256~400 倍，**精确解自己都过不了** | 修一个不可满足的门，每轮都"有进展" |
| H2 | 492 条失败中 **96.5% 来自用例构造**（参考解自身 Inf/NaN、无条件数措施） | 把"用例病态"读成"我们的核不准" |
| H3 | 验收脚本按**整数毫秒**计时 + 无条数断言 + `TEST_F` 完全不可见 | 阈值附近的改动读数上完全看不见 |
| H4 | 为防空统计假绿加的 `validCount > 0`，在输出逐位相等时也开火 | 一次产出 134 个假红；假红比假绿更贵 |

## 通用家族（v2 并入：跨领域的八大家族）

| # | 家族 | 一句话 |
|---|---|---|
| 1 | 契约/语义类 | 验收口径、阈值、输入契约理解错 |
| 2 | 正确性类 | 结果错/不稳定/不可复现 |
| 3 | 环境/构建类 | 工具链/驱动/依赖/构建脚本问题 |
| 4 | 性能关键路径类 | 优化打在非关键路径上（归因不清） |
| 5 | 证据/状态类 | 数字无出处、无复现命令、无证据链 |
| 6 | 工程卫生类 | 临时文件/未归档实验/脏工作区 |
| 7 | 供给侧类 | 对应 H：判据/用例/验收脚本本身的问题 |
| 8 | 装置/门语义类 | 对应 E/F：探针没生效、绿灯语义被误读 |

> 映射：本目录的 A–H 是算子攻坚实例；八大家族是跨领域外壳。
> 新领域实例先归入家族，再看能否映射到 A–H 的具体机制——
> 映射不上 ⇒ 那是新实例，按本表格式追加。
