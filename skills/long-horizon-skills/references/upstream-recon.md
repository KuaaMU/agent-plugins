## 操作面板（先读这一节，再读下面的原则）

**输入**：算子名 + 硬件/版本 + **我正在失败的那个形状段**（用例名、n、batch、实测值、阈值、缺口 %）。
缺少最后一项就别开始——对标的目标是"我失败的那个点"，不是"了解这个算子"。

**输出（落点固定）**：`evidence/<YYYYMMDD>_upstream_recon/FINDINGS.md`，格式见 §3 的表。
**每条对标对象必须填满"我是否已试"列**，只允许 `✅ 已测` / `❌ 未试` / `不适用（附机制）`，**留空即违规**。

**编号工作流**

```
1. 写下失败点：用例名 / n / batch / 实测 µs / 阈值 µs / 缺口 %
2. 按 §1 优先级列候选信源：① 兄弟算子 ② 自己邻带 A/B ③ 上游文档 ④ 竞品
3. 对 ①：在**自己的树里** grep 同形状段的实现（它们已被验收，零可得性风险）
4. 对 ②：翻自己跑过的 A/B —— 尤其"邻带用了另一种表述"那种
5. 对 ③：读参考库 / 官方文档 / 硬件白皮书
6. 对 ④：**先核验它此刻是否可读**（created_at）；不存在属正常，直接记"不存在"即可
7. 每个对象只答 §2 的**四问**，逐条给 `文件:行`（**能被 `sed -n '<行>p' <文件>` 复现**）
   —— 特别是 **①b 家族尺寸参数，必须是数值**；①b 拿不到 ⇒ 标 `①b 未获取`
8. 收尾（§4）：产出 新假设 / 有机制的"不适用" / **新家族的设计输入（尺寸参数）** —— **至少一项**
9. 台账登记：把结论写进 CLAIMS.jsonl（见 ops/long-horizon-attack）
```

**检查点（必须停下等确认）**

| 时点 | 确认什么 |
|---|---|
| 开始前 | 失败点是否写具体了（不是"小 n 慢"，是"<用例> n=小尺寸 差 两位数 %"） |
| 扫描中期 | 是否在产出"技术综述"——**是就立刻收窄到三问** |
| 收尾前 | 每条"不适用"是否都给了机制；给不出的有没有转成待测假设 |
| 落盘后 | `FINDINGS.md` 是否至少产出了一项可执行动作；没有 ⇒ 这次对标等于没做 |

**怎么算做完了**（可机械判定）

```sh
test -f evidence/*_upstream_recon/FINDINGS.md          # ① 落盘
grep -cE '✅ 已测|❌ 未试|不适用' FINDINGS.md          # ② ≥ 对象数（"我是否已试"列无空）
grep -cE '[A-Za-z0-9_./-]+\.(cpp|h|hpp|md|py|cc):[0-9]+' FINDINGS.md   # ③ 出处必须是"路径:行"
grep -cE '[0-9]+ *(KiB|KB|字节|行|线程|次)' FINDINGS.md                 # ④ 有尺寸参数（数值）
```

> **③ 的写法为什么必须是路径形态**：早先写的是 `grep -c ':[0-9]\+'`——
> **那个模式几乎匹配任何"冒号+数字"的文本**（时间、版本串、比值……），
> 于是一份**没有任何真实引用**的报告也能通过。
> **这是判别力检验（§3.0）在验收判据自己身上的应用：先问"它在没有出处时会不会变绿"。**

**四条都过 ⇒ 对标可交付；任一不过 ⇒ 它还是一份"读过而已"。**（见 `long-horizon-attack` 的判别力检验）

每条都能追到具体损失；**它不是通用最佳实践综述**。

# 上游与邻居对标侦察

> **本 skill 补的是过程规程里最弱的一环**：规程能要求"做对标"，
> 但**不能保证对标问的是对的问题**。
> 真实事故：一次覆盖百余个 MR 的上游扫描**读对了**某个已通过验收的兄弟算子的关键结构
> （"**整段相邻尺寸全部走另一种执行安排**"），
> 并用一句"**不同算子，不适用**"打发掉——而最终取胜的方式正是那条路。
> **失手不是"没找到"，是"找到了没当证据"。**

---

## 0. 两条硬规则

> **硬规则 0.1：两个强制时点。**
> **(a) 任务第 0 天**；**(b) 第一个用例失败时**——
> **不是第一个实验失败时，是第一个用例失败时**。成本是小时级，收益是整条路由。

> **硬规则 0.2：「不适用于我」是一条待测假设，不是结论。**
> 写下它时必须附**机制**：*它为什么在这里不成立*（形状不同？容量不够？数据布局冲突？精度要求不同？）。
> **给不出机制 ⇒ 它自动进入 `TASK_ANCHOR` 的未验证假设清单，并标一个证伪实验。**
> **不要用"表述不同"解释掉一条存在性证明——存在性证明的价值恰恰在于表述不同。**

---

## 1. 信源优先级（按**可得性**排序，不是按"像不像对手"）

| # | 信源 | 为什么在这个位置 | 何时可得 |
|---|---|---|---|
| **①** | **同仓 / 同上游的兄弟算子** | 已在你的树里、**已被验收**、可复查 | **现在就可得** |
| **②** | **相邻形状段你自己的 A/B** | 你自己跑的，可复核 | 现在就可得 |
| **③** | 上游参考库 / 公开文档 / 硬件白皮书 | 稳定 | 现在就可得 |
| **④** | **竞品实现** | **通常在你需要它时尚未存在** | 交付物常在**验收之后**才公开 |

> **元规则：任何计划的关键路径，不得经过"一个可能不存在的外部 artifact"。**
>
> **读到任何起决定作用的 artifact ⇒ 当场落盘归档**（源文件 + 二进制进
> `evidence/<gate>/<date>_<topic>/external/`，记 `sha256sum` + commit/ref + 获取命令与 URL）。
> 缺这一步，你的结论会在下一次 `git gc` / 分支删除 / force-push 后变成不可复核。

---

## 2. 只问**四个**问题（其余都是噪声）

对**每一个**对标对象，只回答这四条：

1. **这个形状（n 的范围、batch、布局、dtype）它交给谁算？**
   —— 要**可执行的答案**（哪个 kernel / 哪个执行单元 / 一次还是多次启动），不要"它用了向量化"这种描述。
2. **★ 它那个家族的尺寸参数是什么？**（列跨距 / 行平面高度 / 片上预算 / 线程数 / 启动次数）
   —— **要数值。这一问最容易被漏，而答案往往就在它身上。**
   **"交给谁算"和"按什么尺寸算"是两个问题。** 只回答前者，你会得到一个**单位事实**
   （"它把这个形状段交给了某个执行单元"），而**那个事实可能推出一个错误的动作**——
   例如"那我们也重路由到那个单元"，而**重路由到一个为更大尺寸定尺寸的核，会导致正确性失败**。
   ⇒ **尺寸参数才是可复用的东西；"交给谁算"只是它的标签。**
3. **它的分档是怎么定的——推导出来的还是拍出来的？**
   —— 去找它头文件里的常量与 `static_assert`。手调表 vs 容量推导，直接决定你该抄的是"数值"还是"方法"。
4. **它对我正在失败的那个点怎么处理？**
   —— 只关心**你失败的那个用例的尺寸段**，不要把它整个算子读完。

> **为什么第 2 问要单列（真实代价）**：一次攻坚里，扫描拿到的结论是
> 「某个已通过验收的兄弟算子把一段尺寸区间**整段交给了某一种执行安排**」。
> **这个结论是对的，但它诱导出一个错误的动作**——"那我们也把这段重路由到那种安排"，
> 而实测**正确性直接失败**。取胜的那份实现做的**不是重路由**，而是
> **写了一个按固定行平面 / 一次性启动定尺寸的**新家族**。
> **那个尺寸参数，原来那三问里没有一问会问到它。**

> ### ① 与 ①b 冲突时：**以 ①b 为准**
>
> 它们不是同一问题的两面，是**两个不同的事实**：
>
> | | 问的是 | 可复用性 |
> |---|---|---|
> | **①** | **交给哪个单元 / 哪个内核** | **标签**——换个实现就变 |
> | **①b** | **那个家族按什么尺寸定的** | **实体**——这才是能抄的东西 |
>
> **冲突只发生在一种情形，而它正是最危险的一种**：**单元相同、尺寸不同**。
> 这时 ① 会说"它和我们一样，没什么可学"，而 ①b 会说"它按形状定尺寸"。
> **照着 ① 的答案去做，就会得到"重路由"——而那个动作已被实测否掉（精度失败）。**
>
> **⇒ 规则：答案冲突时以 ①b 为准；①b 答不出来 ⇒ 该条对标不算完成**
> ——标 **`①b 未获取`**，并明确写"**不足以作为设计输入**"。
>
> **④（外部提交）的强制例外**：对竞品 / 外部提交**①b 常常根本答不出**
> （拿不到源码，只拿得到它的声明）。那就**必须显式降级**，在报告里写明：
> **「④ 通常只能回答 ①；单凭 ① 不得作为设计输入。」**
> 不写这句，读者就只会看到 ①，然后去重路由——**那正是实测被否掉的动作。**

> **可复制的检索 prompt 模板**（交给子 agent 时照抄，只改 `<...>`）：
>
> ```
> 只读。禁止编辑源码、禁止写 git 工作树、禁止运行任何构建/测试/采集命令。
>
> 目标：算出 <算子名> 在 <硬件> + <工具链版本> 上，
>      形状段 <n 范围 / batch / dtype> 应当由哪套执行安排来算。
>
> 对下列每一个对象，**只回答四个问题**：
>   ①  这个形状它交给谁算？（给出 kernel 名 / 执行单元 / 启动次数，要可执行）
>   ①b **它那个家族的尺寸参数是什么？**（列跨距 / 行平面高度 / 片上预算 /
>       线程数 / 启动次数 —— **要数值**。"交给谁算"和"按什么尺寸算"是两个问题。）
>   ②  它的分档是推导的还是拍的？（引它的常量与 static_assert 原文与行号）
>   ③  它对我失败的那个点（<用例名、n、实测值与阈值的缺口>）怎么处理？
>
> 对标对象（按此顺序）：
>   ① 本仓/本上游内**同形状段**的兄弟算子：<列出候选>
>   ② 本仓内**相邻形状段**的实现：<列出候选>
>   ③ 上游参考库 / 官方文档 / 硬件白皮书
>   ④ 竞品 / 外部提交（若存在；**不存在属正常，直接说明即可**）
>   **⑤ 另外列出你发现的、上面清单之外的同形状段实现。**
>      （列清单的人列不出他不知道的东西——这一条就是为补这个漏。）
>
> 输出格式：每个对象一小节，只写这四问的答案 + 原文引用（文件:行）。
> **每条 `文件:行` 引用必须能被 `sed -n '<行>p' <文件>` 复现；我会抽查。**
> **禁止**输出"技术体系综述"、"设计理念总结"或与被测形状无关的部分。
> 若你判断某个对象的做法**不适用**，必须写出**机制**（为什么在这里不成立）；
> 写不出机制 ⇒ 标为「待测假设」并给出最小证伪实验。
>
> 报告落盘到 <路径>，回复：三条最关键的结论 + 路径。
> ```

> **这份模板本身就是产物**：一次真实扫描之所以产出"技术清单"而不是"尖答案"，
> 就是因为任务书写的是"扫一遍上游"，而不是上面这四问——
> **再加上漏了 ①b，于是拿到一个正确但会误导动作的结论。**

> **这份 prompt 自己也需要验证（它现在是 `未受攻击`）。**
> 有一个天然的正样本：**拿一个已知形态的兄弟算子当被测对象跑一遍这个 prompt**，
> 看它是否同时产出「它把哪一段交给了谁」**和**「那个家族的尺寸参数」。
> **只产出前者 ⇒ 这份 prompt 在被测事故上的判别力是 0，而这是可以实测出来的结论。**

## 3. 输出格式（落 `evidence/<date>_upstream_recon/FINDINGS.md`）

| 对标对象（**含版本/commit**） | 它对这个形状 | **★ 家族尺寸参数**（列跨距/行平面/预算/线程/启动次数） | 交给谁算（可执行） | 分档：推导/拍 | 它对我失败点怎么处理 | 出处 | 我是否已试 |
|---|---|---|---|---|---|---|---|
| `<repo>@<commit>` | | **数值** | | | | `文件:行` | ✅/❌/**不适用（机制）** |

**「★ 家族尺寸参数」列不允许空，也不允许写"用了向量化"这类描述——必须是数值。**
它是本表**唯一可以直接复用的东西**；"交给谁算"只是标签。
**④（外部提交）那一行若拿不到源码，本列填 `①b 未获取`，并注明"单凭 ① 不得作为设计输入"。**

**「版本/commit」必须写**：被读的是一棵会变的树。没有版本号，同样的行号明天指的可能是别的东西
（与"读到的外部 artifact 当场落盘"是配套的两件事）。

**「我是否已试」这一列只允许三种取值**：
`✅ 已测` / `❌ 未试` / **`不适用（此处必须写机制）`**。
**留空 = 违规。**

---

## 4. 收尾：把结论转成动作

对标做完后，**必须**产出其中至少一项，否则这次对标等于没做：

- 一条**新的可测假设**（进 `TASK_ANCHOR` 的未验证假设清单，附最小实验）；或
- 一条**有机制的"不适用"**（写清楚为什么，供后来人复查）；或
- 一个**新家族的设计输入**（切点、容量预算、启动次数——见 `execution-family-design`）。

> **一句话**：**对标的目的不是"了解别人在做什么"，而是"逼出一个我还没试过的安排"。**
> 一份读完了却不改变任何行动的扫描报告，和没读的区别只是多花了半天。
