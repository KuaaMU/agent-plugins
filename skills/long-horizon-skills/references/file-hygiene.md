# §13 文件财政纪律

目标：agent 的每一次写文件都回答三个问题——写给谁看、保留多久、谁负责删。
文件混乱不是整理问题，是写入无门禁问题。

## 目录契约

`mission/` 下长期存在的只有固定名单（见 `state-files.md` 十个权威文件）。
其他一切按去处分流：

| 去处 | 内容 | 生命周期 |
|---|---|---|
| `scratch/<候选ID>/` | 实验产物：脚本、中间数据、调试输出 | 候选 close 时整个目录归档或删除 |
| `research/` | 联网/外部资料笔记 | 每个文件头必须有：来源、日期、一句话结论；超量触发配额规则 |
| `evidence/<run>/` | 原始证据：manifest、命令、日志、hash | 永久，随任务归档 |
| `worklog/` | 过程笔记，append-only | 定期提炼后归档，不作验收证据 |
| `archive/` | 被取代的报告、已关闭候选的 scratch | 只读 |

WHEN 不知道文件该放哪 THEN 放 `scratch/`——默认可删除，
而不是默认永久。

## 搜索配额

WHEN 需要联网找思路 THEN 遵守预算：
- 每轮最多 N 次搜索/爬取（建议 N=5，任务开始时定死）；
- `research/` 下文件数超 K（建议 20）→ 强制先读完、消化、提炼，
  不许搜新的；
- 工具降级链：官方文档/API > curl > 定向爬取 > 浏览器自动化。
  重型浏览器工具 flaky 是常态，放最后，能不用就不用。

WHEN 同一个问题已搜过两轮无新信息 THEN 停止搜索，
转为本地最小实验——搜索的边际收益递减比你想象的快。

## 远端隔离（SSH/容器/远端机）

- 远端只跑代码：agent 的笔记、分析、结论一律写本地，
  不许写远端工作区；
- 每次只取回"证据文件"（log 摘要、benchmark CSV、manifest），
  原始大文件留远端，定期清理；
- WHEN 分不清某文件是"跑代码产物"还是"agent 写的" THEN
  它就是没人认领的文件 → 按 scratch 处理，任务结束删除；
- 容器/会话到期前强制 checkpoint：取回证据、更新 HANDOFF；
- 任务结束清空远端工作区，只留 manifest 索引。

## 执行机制

`mission_lint.py` 检查：
- `scratch/` 下有无孤儿目录（候选已 close 但目录还在）→ ERROR；
- `research/` 文件数超配额 → WARN；
- 权威文件外的 `.md` 在 `mission/` 根目录游荡 → WARN；
- `evidence/` 下 manifest 缺失 → WARN。
