# 结构化执行状态 —— schema 与用法

> 这份文档定义的是一件事：**每轮实验只读一个对象，而不是读完全部历史再自己重建。**
>
> 它吸纳自 SKILL.state（arXiv `2608.26263`，`accepted at EMNLP`）的三个机制，
> 并按本仓的粒度（**实验**，不是 tool call）重新定尺寸：
>
> | 采纳的机制 | 在本仓里落在哪 |
> |---|---|
> | 状态外置为一个**固定 schema 的对象** | `state.json`（`state-schema.md` §1） |
> | **稀疏补丁**，`null` 表示删除 | `state_patch.py`（`state-schema.md` §2） |
> | **校验门**：没通过校验的补丁不生效，但拒绝进审计日志 | `state_patch.py`（`state-schema.md` §3） |
>
> **本仓不取的**：它的 runtime 与平台适配器（本仓是一组检查，不是运行时）；
> 以及它的"推理立即丢弃"——本仓恰恰要求**把推理留在可审计的地方**，
> 那就是增量 Markdown 日志（本页 §2）。所以这里是**双轨**：
> **JSON 是唯一真相源，Markdown 是它的增量派生视图**（硬规则 `2.5.3`）。

## 1. 为什么是这一组字段（而不是别的）

**每加一个字段，先回答一句：「它让哪条已有规则能开火？」答不上来就不加。**
下面每一行都能回答。**一条答不上来的字段，就是这一页正在变成第二份 `CURRENT_PLAN.md` 的信号。**

| 字段 | 它让哪条规则开火 | 没有它会长什么样 |
|---|---|---|
| `frame.name` / `frame.status` | `1.1` 继承的框架是假设 | 没人问"这个形状为什么由它算" |
| `frame.falsifier` / `frame.next_if_falsified` | `1.2`（强化） | 写不出 ⇒ 是信仰不是假设，不会被证伪 |
| `failure_set[]`（逐例名 + 缺口） | `4.3` / `4.4` | 无逐例记录 ⇒ 停滞不可判 |
| `gap_now_pct` / `gap_history` / `budget_rounds` | **`4.6` 量级外推** | 唯一不需先自我怀疑的触发器 |
| `excluded_paths[]`（带失效标记 + 证据） | `null` 语义 | 无失效标记的条目 = 暗中生效的假设 |
| `claims_ref` | `2.5.1` 台账 | 只放路径不放内容（防漂移 `2.5.3`） |

### 与台账的关系（两件，各管一段，不重叠）

| 件 | 管什么 | 谁读 | 谁保证它不漂 |
|---|---|---|---|
| `CLAIMS.jsonl`（+ `claims_lint.py`） | **证据状态**：凭什么信、等级、失效传播 | 人 + lint | 有工具 |
| **`state.json`（+ `state_patch.py`）** | **执行状态**：当前框架 / 失败集合 / 缺口趋势 / 已排除路径 | 工具 + Agent | 有工具（校验门） |

> **「每轮只读一屏」就是 `--show` 的输出，不是第二份文件。**
> 曾经有一个手写的 `FRAME.md` 承担这个角色，**已并入 `state.json`**——
> 它的字段是这里 schema 的真子集，两份并行维护只会漂（硬规则 `2.5.3`）。
> **一屏是渲染，不是资产。**

## 2. 增量 Markdown 日志

`--log` 指向一个**只追加**的 Markdown 文件。每轮写一条：

```markdown
## APPLIED  r4  2026-09-14T04:13:46Z
- gap_now_pct ← -12.4；round ← 4；gap_history 追加 r4
- **4.6 外推**：10 轮 × 0.933 %/轮 = 9.33% vs 缺口 15.20% → 不可达
```
被拒绝的写 `## REJECTED  r5 …`（写明状态未改动、拒绝原因、原补丁）。
分工：JSON 是**当前状态**（覆盖写），Markdown 是**增量历史**（只追加）；
矛盾时以 JSON 为准。

### 完整示例（由工具真实生成）
`state.example.json`（第 4 轮状态）+ `EVENTS.example.md`（4 条 `APPLIED` + 1 条 `REJECTED`）：
一条无失效标记的排除条目被挡在门外，**状态逐字节未动**——这是设计意图。
示例必须能过校验门，schema 变动后同步更新。

## 3. 边界（诚实声明）

- **这套东西不替你判断。** 它把 4.6 那一行**算出来并写在每轮日志里**，
  但"算出来不可达之后要不要换框架"仍然是人的决定。工具只保证**那个数不会缺席**。
- **它管执行状态，不管证据状态。** 证据在 `CLAIMS.jsonl`；
  这里只有一条 `claims_ref` 指过去——**不复制**（`2.5.3`）。
- **它不保证 schema 就是对的。** 字段集是从本仓现有的规则**倒推**出来的；
  如果你的任务里有规则用不上这些字段，那说明该改的是 schema，而且改之前要先回答 §1 那个问题。
- **未命中 ≠ 干净。** 校验门拦的是它列出的那些形态；它没列出的形态它看不见。

## 4. 合并扩展字段（v2 并入）

| 字段 | 它让哪条规则开火 |
|---|---|
| `candidates_summary` | §12 赛马：记分牌摘要（各候选 ID / 状态 / 最新结果），详情在 `CANDIDATES.md` |
| `hard_set_ref` | §14 困难集：指向 `HARDSET.md`；困难集用例不进日常评分 |
| `round` | §11 外循环：当前轮次；§12 处决周期计数基准 |

`CANDIDATES.md` 是候选明细的权威（§2.5.3：明细只写一处）；
`state.json` 只放摘要与指针，不复制明细。
