# 结构化执行状态 —— schema 与用法

> 这份文档定义的是一件事：**每轮实验只读一个对象，而不是读完全部历史再自己重建。**
>
> 它吸纳自 SKILL.state（arXiv `2608.26263`，`accepted at EMNLP`）的三个机制，
> 并按本仓的粒度（**实验**，不是 tool call）重新定尺寸：
>
> | 采纳的机制 | 在本仓里落在哪 |
> |---|---|
> | 状态外置为一个**固定 schema 的对象** | `state.json`（本页 §2） |
> | **稀疏补丁**，`null` 表示删除 | `state_patch.py`（本页 §3） |
> | **校验门**：没通过校验的补丁不生效，但拒绝进审计日志 | `state_patch.py`（本页 §4） |
>
> **本仓不取的**：它的 runtime 与平台适配器（本仓是一组检查，不是运行时）；
> 以及它的"推理立即丢弃"——本仓恰恰要求**把推理留在可审计的地方**，
> 那就是增量 Markdown 日志（本页 §5）。所以这里是**双轨**：
> **JSON 是唯一真相源，Markdown 是它的增量派生视图**（硬规则 `2.5.3`）。

---

## 1. 为什么是这一组字段（而不是别的）

**每加一个字段，先回答一句：「它让哪条已有规则能开火？」答不上来就不加。**
下面每一行都能回答。**一条答不上来的字段，就是这一页正在变成第二份 `CURRENT_PLAN.md` 的信号。**

| 字段 | 它让哪条规则开火 | 没有它会长什么样 |
|---|---|---|
| `frame.name` / `frame.status` | `1.1` 继承的框架是假设 | 一条路由跑了两年没人问过"这个形状为什么由它算" |
| `frame.falsifier` / `frame.next_if_falsified` | `1.2`（强化） | **写不出这两句 ⇒ 它不是假设，是信仰**——信仰不会被证伪，于是整场攻坚在里面"一直有进展" |
| `failure_set[]`（逐例名 + 缺口） | `4.3` / `4.4` | 没有逐例记录，停滞不可判，于是"做了几轮"成为唯一可见的量 |
| `gap_now_pct` / `gap_history` / `budget_rounds` | **`4.6` 进展的量级外推** | **本仓唯一一条不需要先自我怀疑就能开火的换框架触发器**——它需要一个你本来就在测的量，和它的趋势 |
| `excluded_paths[]`（带失效标记 + 证据） | `null` 语义 / 规则 `3.0.2` | 只增不减的排除清单，让每一轮都重新判断"它还算不算数"。**没有失效标记的条目 = 一个还在暗中生效的假设** |
| `claims_ref` | `2.5.1` 台账 | 把台账条目复制进状态 ⇒ 两处都会漂移（`2.5.3`）。**这里只放路径，不放内容** |

### 与台账的关系（两件，各管一段，不重叠）

| 件 | 管什么 | 谁读 | 谁保证它不漂 |
|---|---|---|---|
| `CLAIMS.jsonl`（+ `claims_lint.py`） | **证据状态**：凭什么信、等级、失效传播 | 人 + lint | 有工具 |
| **`state.json`（+ `state_patch.py`）** | **执行状态**：当前框架 / 失败集合 / 缺口趋势 / 已排除路径 | 工具 + Agent | 有工具（校验门） |

> **「每轮只读一屏」就是 `--show` 的输出，不是第二份文件。**
> 曾经有一个手写的 `FRAME.md` 承担这个角色，**已并入 `state.json`**——
> 它的字段是这里 schema 的真子集，两份并行维护只会漂（硬规则 `2.5.3`）。
> **一屏是渲染，不是资产。**

## 2. schema

```json
{
  "schema_version": 1,
  "task": "<一句话：这次攻坚要达成什么>",
  "round": 0,

  "frame": {
    "name": "<当前框架：用哪条路径 / 哪套家族>",
    "status": "假设 | 已验证 | BLOCKED",
    "falsifier": "<证伪它的具体实验：跑什么、看什么判据>",
    "next_if_falsified": "<它被证伪之后走哪条路>"
  },

  "failure_set": [ { "case": "<用例名>", "gap_pct": -15.2 } ],

  "gap_now_pct": -15.2,
  "gap_history": [ { "round": 3, "gap_pct": -12.4 } ],
  "budget_rounds": 10,

  "excluded_paths": [
    { "path": "Cube 路径", "marker": "refuted",
      "reason": "+28% 上限，量级不够", "evidence": "control/BLOCKED.md" }
  ],

  "claims_ref": "mission/CLAIMS.jsonl"
}
```

**两条硬纪律：**

1. **`_pct` 后缀是单位，不是装饰。** 缺口一律**百分数**：`-15.2` 表示"还差 15.2%"。
   字段名里不带单位时，这套东西出过一次真实的 100× 错误（`-0.152` 被当成 `-0.152%`，
   于是"不可达"被判成"可达"）。**单位写进名字，就丢不掉了**（硬规则 `2.1`）。
2. **`gap_history` 与 `round` 由工具维护，补丁里不许出现。**
   工具在每次合并后自动把 `gap_now_pct` 追加成一行趋势。
   让调用方自己发整段历史，就是把它退回"每轮重发全部状态"——那正是这套东西要消灭的。

`marker` 取值：`refuted` / `superseded` / `invalidated` / `INVALID` / `已闭合`。

**`budget_rounds` 可以缺席。** 「我还没设预算」是一个**真实状态**，
逼它填一个数字会造出一个假数字，而假数字会被当真算进 4.6。
缺席时 4.6 会**明说「预算未设定」**，而不是给出一个可达/不可达的结论——
**让缺的东西可见，比让缺的东西变成一个默认值好。**

## 3. 补丁：稀疏 + `null` 删除

一份补丁**只写变了的字段**：

```json
{ "gap_now_pct": -12.4,
  "excluded_paths": [ { "path": "非 2 的幂车道切分", "marker": "refuted",
                        "reason": "预测 −21%，实测 −0.1%", "evidence": "evidence/.../REFUTED.md" } ] }
```

```bash
python3 scripts/state_patch.py --state state.json --log EVENTS.md --patch p.json
```

- **没提到的字段不动。**
- **`null` 表示删除该键**：`{ "gap_now_pct": null }` 会把这一项**删掉**，而不是置空。
  这是"过时的前提要被显式删除"的落点——让下一个读状态的人**根本看不到它**，
  而不是每轮都要重新判断"这条还算不算数"。
- 数组（`failure_set` / `excluded_paths`）**整体替换**，不是逐项合并。
  理由：这两者的正确语义是"此刻的实际情况"，逐项合并会产生既不是旧值也不是新值的东西。

## 4. 校验门

**补丁先过校验，通过了才合并。没通过 ⇒ 状态逐字节不动**，但"被拒绝"这件事进日志。

它会拦下这些（每一条都对应一条已有规则）：

| 拦截 | 对应规则 |
|---|---|
| `frame.falsifier` / `next_if_falsified` 为空 | `1.2` 强化 —— 写不出就不是假设 |
| `frame.status` 不在 `假设/已验证/BLOCKED` | 状态枚举固定，防止自由发挥 |
| `excluded_paths[]` 缺失效标记 | `null` 语义 —— 没有标记的条目还在暗中生效 |
| `excluded_paths[].evidence` 为空 | 与 `claims_lint` ⑤ 同源：**既无证据又无推导来源的断言不许进状态** |
| `failure_set[].gap_pct` 不是数字 | `4.6` 的输入必须是可算的量 |
| `gap_history[].round` 未严格递增 | 趋势要求按轮次单调，否则趋势没有意义 |
| **未声明的顶层键** | schema 固定。**想加字段先回答"它让哪条规则开火"** |
| 补丁里出现 `round` / `gap_history` | 由工具维护。**显式拒绝，不是静默忽略**——静默忽略会让"我提交了它"与"我没提交"输出同值（E7 的形态） |

> **拒绝不是失败。** 一次被拒绝的补丁把"我打算这么改但没通过"记在日志里，
> 而状态保持干净。**这比让一个半对的补丁悄悄生效要好得多。**

## 5. 增量 Markdown 日志

`--log` 指向一个**只追加**的 Markdown 文件。每轮写一条：

```markdown
## APPLIED  r4  2026-09-14T04:13:46Z

- gap_now_pct  ← -12.4
- round  ← 4（自增）
- gap_history  ← 追加 r4: -12.40%（共 4 点，趋势由工具维护）

- **4.6 外推**：10 轮 × 0.933 %/轮 = 9.33%  **vs 当前缺口 15.20% → 不可达**
```

被拒绝的写 `## REJECTED  r5 …`，**并在里面写明状态未改动、拒绝原因、以及原补丁**。

它和 `state.json` 的分工：JSON 是**当前状态**（覆盖写，读的人看到的就是现在），
Markdown 是**增量历史**（只追加，回答"我是怎么走到这里的"）。
**两者矛盾时以 JSON 为准。**

### 完整示例（**由工具真实生成，不是手写的**）

| 文件 | 是什么 |
|---|---|
| [`state.example.json`](state.example.json) | 一个走到**第 4 轮**的状态对象：框架已 `BLOCKED`、失败集合两例、趋势三点、两条已排除路径 |
| [`EVENTS.example.md`](EVENTS.example.md) | 它对应的**全部增量日志**——4 条 `APPLIED` + **1 条 `REJECTED`**，含被拒绝的原因原文 |

两者合起来就是一个真实任务运行到一半时的样子。**注意那条 `REJECTED`**：
一个没有失效标记、也没有证据的排除条目被挡在门外，**而状态逐字节未动**——
这是设计意图，不是失败。

> **它们必须能过校验门。** 仓库的自检脚本（**不在安装产物里**）会在 schema 变动后立刻发现示例过期——
> 否则示例会慢慢变成一份"教人写通不过校验的东西"的文档。

## 6. 边界（诚实声明）

- **这套东西不替你判断。** 它把 4.6 那一行**算出来并写在每轮日志里**，
  但"算出来不可达之后要不要换框架"仍然是人的决定。工具只保证**那个数不会缺席**。
- **它管执行状态，不管证据状态。** 证据在 `CLAIMS.jsonl`；
  这里只有一条 `claims_ref` 指过去——**不复制**（`2.5.3`）。
- **它不保证 schema 就是对的。** 字段集是从本仓现有的规则**倒推**出来的；
  如果你的任务里有规则用不上这些字段，那说明该改的是 schema，而且改之前要先回答 §1 那个问题。
- **未命中 ≠ 干净。** 校验门拦的是它列出的那些形态；它没列出的形态它看不见。
