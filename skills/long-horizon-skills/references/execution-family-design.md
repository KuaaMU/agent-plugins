# 形状 → 执行家族：设计与推导

> 它补的结构性空缺：切分设计类 skill 都**假定执行模型已选好**，
> 没有一个回答"**这个形状该由哪套模型算，以及为什么**"。
> 真实事故：一个算子的小尺寸段走通用线程式路径两年无人问过为什么；
> 相邻形状段走向量路径，实测快数倍——证据就在自己的实验记录里，
> 却被读反了主语。

## 操作面板

**输入**：算子名 + host 侧路由源码路径 + 硬件型号/工具链版本。
**输出**：`<算子>_FAMILY_AUDIT.md`（§1 审计表 + §3 容量推导 + "新开家族 vs 继续调优"判定）。

**工作流**：读 host 侧全部分支 → 逐条抄成 §1 的表（每行标 假设/已验证/红旗）
→ 抽硬件常量 → 容量推导 + `static_assert` → 不达标形状段做 §4 三条检验
→ 三条全中 ⇒ 停微杠杆，转新家族/对标。

## 0. 三条硬规则

**0.1 继承来的路由是假设，不是给定条件。** 对分档表**每一行**问：
"这个形状为什么由它来算？"答不上来 ⇒ 标**未验证假设**，给最小证伪实验。

**0.2 分档必须可推导。** 阈值由容量/位宽/连续尺寸范围算出，
写成 `static_assert` 让编译器守。**手调常数表是技术债**——
它让所有人不敢动架构，于是努力全流向"在旧路径上调优"。

**0.3 「这条路径没有余量」≠「这个问题没有余量」。**
忙管 >95%、算术已在下界、结构项全排除之后，只允许：
**换表述**（新家族）或**对标外部**。继续微杠杆是禁止项。

## 1. 家族审计（接手时的第一个动作）

| 形状段 | 当前由谁算 | 为什么 | 状态 | 证据 |
|---|---|---|---|---|
| <小尺寸段> | `<kernel>` | ? | **假设/已验证** | |

"为什么"三联判：
- 写得出**容量/位宽推导** ⇒ 已验证，附推导；
- 写"一直如此/继承来的" ⇒ **假设**，进未验证清单；
- 写**特例**（`n == <定值> && batchSize >= <定值>`）⇒ **红旗**：
  这张表是对着测试用例调的，不是对着硬件算的。

## 2. 执行模型选择：先看形状，再看容量

| 模型 | 什么时候是它 |
|---|---|
| **SIMT**（线程式） | 逐元素、条件分支多、不规则访问 |
| **SIMD**（向量寄存器） | 规则形状、可整块向量化、**车道能被填满** |
| **矩阵/tensor 单元** | 稠密矩阵乘、维度够大能摊薄启动与搬运 |
| **混合** | 主体规则 + 边角不规则（拆开的代价 < 收益） |

**最容易错的是 lane 利用率**：约一半尺寸的形状放进按整尺寸定尺寸的向量核，
会在**半空的平面上做满宽运算**——不是向量模型不适合小尺寸，
而是**这个核不是为这个形状定尺寸的**。模型的适用性和内核的尺寸**分开判**。

## 3. 容量推导：让阈值算出来，让编译器守

```cpp
// ① 硬件常量：从 platform 接口取，不要硬编码
constexpr uint32_t kVectorWidth = kVectorWidthFromPlatform();
constexpr uint32_t kThreadsPerGroup = kThreadsPerGroupFromPlatform();
// ② 家族切点：由硬件常量导出，不是拍的
constexpr uint32_t kPackedMaxRows = kThreadsPerGroup;
constexpr uint32_t kVectorRows    = kVectorWidth;
// ③ 预算：由容量推导
constexpr uint64_t kDynamicBytes = /* 布局算术推导 */;
constexpr uint64_t kTotalBytes   = /* 片上实际可用 */;
static_assert(kDynamicBytes <= kTotalBytes, "片上预算超了");
```

收益不是"优雅"是"可改"：改布局时阈值自动跟着变。
**诚实边界**：预算常是"推导 + 标定"混合——可以，但必须区分：
**切点来自硬件常量（可推导），预算来自标定（写清是标定值）**。
把标定值伪装成推导值，就是在造假证据。

## 4. 决策：在旧路径上调优，还是新开一个家族？

**§4.0 先看这一条：尺寸不匹配 ⇒ 做一次"错配核算"**（不是直接判换）：
- (a) 被浪费的资源在不在绑定管上？若浪费的是掩码 lane/未用预算，
  而绑定管占用率已近 100% ⇒ **这个浪费是免费的**（实测：消除约 1/3
  lane 浪费的实验，预期两位数收益，实测接近零）；
- (b) 用例是不是固定开销主导？（小 n 且小 batch 的延迟型）⇒ 先解决固定开销。
- 两项都指向"错配确实在花钱" ⇒ 判"新开家族"；否则回落到下面三条。
- ⚠️ 动作是"**新开一个为该形状定尺寸的家族**"，不是"重路由到已有核"——
  实测反例：把小尺寸段重路由到按 2 倍尺寸定尺寸的核，**正确性直接失败**。

**以下三条适用于"尺寸匹配、或错配核算判定为免费"的情形，满足全部三条才停：**

1. **忙管 >95%**；**且**
2. **算术已达算法下界**（**写下界**，不是"看起来不多"）；**且**
3. **结构项全部排除**（访存冲突、lane 利用率、同步、竞争、调度，逐项）。

真实代价：某战役三条早已同时成立且被正确测出，结论却写成"大概是形成层极限"，
此后又做了 4 轮微杠杆实验全被否。正确推论是"**这条路径没有余量 ⇒ 该换形状**"。
**禁止的是"微杠杆"，不是"实验"**——照做就是去写一个为该形状定尺寸的新内核。

**新家族的形状从哪来**（按可得性排序，见 §6）：
① 同仓/同上游的兄弟算子（同形状段已用另一种安排通过）；
② 相邻形状段自己的 A/B；③ 上游参考库/文档/白皮书；
④ 竞品——通常在你需要它时不存在，**不得放入关键路径**。

## 5. 反模式清单

| 反模式 | 改成 |
|---|---|
| 手调常数表 + 特例 | `constexpr` 推导 + `static_assert` |
| 阈值 = "能通过测试的最大值" | 写容量推导 |
| 单文件几千行、家族全挤在一起 | 薄启动器 + 共享库 |
| 一个家族覆盖过宽的 n 段 | 按形状分家族 |
| "先调优，架构以后再说" | 先做 §1 家族审计 |

## 6. 最小工作流

```
1. 读 host 侧路由，填 §1 审计表；每行标 假设/已验证/红旗
2. 每个"假设"行：这个形状为什么由它算？→ 进未验证假设清单
3. 每个家族容量推导（§3）；标出所有手调特例
4. 不达标形状段：§4.0 错配核算 → 三条检验
   全中 ⇒ 停微杠杆，转新家族 / 对标
5. 新家族：先算容量预算写成 static_assert，再写代码
```

> **一句话**：**分档表是这个算子的架构声明。**
> 如果它是手调的，那这个算子就没有架构，只有一堆对着测试调出来的数——
> 而在没有架构的地方，所有优化努力都会流向"把错的路径调快"。
