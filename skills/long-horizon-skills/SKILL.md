# 长程攻坚防失效规程

> **本规程针对的失效模式**：不是"不够努力"，而是**框架锁死**、**自证偏差**、**目标漂移**、
> **装置失效**、**门语义失效**、**证据强度失配**。
> 六者都不会表现为"做不下去"，而会表现为"一直在正常推进"——这正是危险之处。
>
> **其中"装置失效"最隐蔽**：它让一次**没跑过**的实验产出一份**格式完整、数字整齐、结论有机制解释**的记录，
> 而所有常规纪律（预注册、A/B/A 对照、精度门、独立复核）**全部通过**。

## 0. 何时加载 · 本 skill 的框架 · 怎么用

### 0.1 何时加载（满足**任意两条**）

- 目标是一个**硬性数值指标**（如通过率 `N/N`、延迟 ≤ X），需要多天/多周；
- 预计要做 **≥ 5 个实验**，且每个实验都要改生产代码；
- 目标是在**他人已有代码**上继续（接手、继承、或自己上一轮留下的树）；
- 存在**外部同类实现**（上游 PR、竞品提交、参考库）。

### 0.2 框架：四层，按「**什么时候进上下文**」分

> 这一层划分是**照着 agent 工具实际的加载模型**定的（Claude Code / Codex 一类）：
> 常驻的只有 `description`；**技能被调用时**才载入正文；`references/` 与 `scripts/`
> **只在需要时读或跑**。所以"框架"要回答的是"**哪一层放什么**"，不是"文件怎么摆"。

| 层 | 什么时候进上下文 | 放什么 | 载体 | 预算 |
|---|---|---|---|---|
| **L0 触发** | **常驻**（每次会话） | `name` + `description`：什么时候该用本 skill | frontmatter | ≤ 300 字 |
| **L1 操作** | **技能被调用时** | 七条原则 · 第 0 天流程 · 每轮闭环 · **规则索引**（一行一条） · 工具入口 | 本文件正文 | 目标 **≤ 250 行** |
| **L2 详读** | **agent 按需读** | 每条规则的完整正文（含**它对应的真实代价**）· 失效目录 · 模板 · schema | `references/*.md` | 按需，不进常驻 |
| **L3 执行** | **调用时** | 三个工具；各自 `--self-test` 自证会开火 | `scripts/` | **0**（脚本不进上下文） |

**三条关键约定**：

1. **L1 里的规则是「索引」，不是「规则本身」**——一行一条，形如
   `4.6  开跑之前先写下"如果有效，失败集合会怎么变"`。
   扫一遍索引就知道这一轮该去 L2 读哪条，**不必把全部规则读进来**。
2. **规则编号（`§4.6` 这种）是跨文件的主键**，无论正文放在哪一层都不改号。
   引用规则一律用编号，**不要复述正文**（`2.5.3`：同一个量只能有一处权威来源）。
3. **规则的权威正文在 L2**。L1 索引与 L2 正文冲突时以 **L2** 为准；
   L2 与任何"复述"冲突时以 **L2** 为准。

> **现状（诚实声明）**：本章定义的是**目标框架**；**L1 目前尚未裁到 250 行**
> （正文仍是把 L2 内容内联在一起的历史形态）。裁切的分界线已经定死：
> **命令式的规则句留在 L1，它对应的「真实代价」叙事移进 L2**——
> 代价是规则的权威来源，所以它不能删，只能搬家。

### 0.3 怎么用（编排者的三条路径）

| 你在哪 | 读什么 | 产出 |
|---|---|---|
| **刚拿到任务书** | `references/asset-index.md` §4「从任务书到第一个实验」 | `TASK_ANCHOR` + `CLAIMS.jsonl` + `state.json` |
| **每轮实验** | 本文件 §10 闭环；按需读 L2 里被索引指到的那几条 | 一份状态补丁 + 一条台账 |
| **宣布完成前** | §9 完成判据 + 独立审计者 | 逐字重述判据 + 实测值比对 |


## 1. 任务锚定（Task Anchor）—— 对抗"忘了起始点"

**在写任何代码之前**，建立 `TASK_ANCHOR.md`（模板见 `references/anchor-template.md`），至少包含：

| 项 | 要求 |
|---|---|
| 目标原文 | **逐字**抄写验收条件，不改写、不概括 |
| 验收判据 | 判定式、阈值来源、**谁有权改**（明确写"我没有"） |
| **起始点** | 当前实测状态 + commit + 二进制哈希 + 此刻的失败集合（**逐一列名**） |
| 当前框架 | 用哪条路径/哪套架构，**以及为什么**——并显式标注它是**继承来的假设**还是**已验证的结论** |
| 未验证假设 | 逐条列出"我接受了但没测过"的东西 |

> **硬规则 1.1**：**继承的框架是假设，不是给定条件。**
> 每一条"因为历史原因就是这样"的路由、阈值、分档，都必须能被问一句：
> **"这个形状为什么由它来算？"** 答不上来，就把它标为待验证。
>
> **硬规则 1.2**：**每完成 N 个实验（N ≤ 5）或每 24 小时，强制重新锚定一次。**
> 重新锚定 = **不看自己的旧总结**，从原始证据重建：目标是什么、起始点在哪、什么已被证伪、当前框架是什么、它还是假设还是已升级为结论。
>
> **重锚时"当前框架"那一栏必须多写两句**：**证伪它的具体实验是什么**、**它被证伪之后走哪条路**。
> **写不出这两句 ⇒ 它不是一个假设，是一个信仰**——信仰不接受证伪，也就不会被证伪，
> 于是整场攻坚会在它里面**一直"有进展"地走下去**。见 §4.6。
>
> **硬规则 1.3**：**先读被测对象本身，再对本体的行为建模。**
> 在写下任何"输入数据大概是什么分布""这个用例长什么样"之前，**去读测试数据生成器与用例表原文**
> （示例：测试源码里的**用例生成函数**与 `cases/*.csv` 用例表）。
> 一次 grep 能排除整类假说，而它会排在你做四次实验之后——如果你不去读。
> 真实事故：一条"随机输入必有近零对角元 ⇒ 某个快速分支不成立"的**算术上合理**的推断被写进预注册，
> 并得到复核者背书；而**用例生成器给对角加了偏移**，那条判据在实际用到的尺寸上**恒为真**。
> 实测把整轮实验推翻。**一次读用例生成器源码就能避免。**

> **硬规则 1.5：锚定档有一个机器形态，每轮只读它一个对象。**
> `TASK_ANCHOR.md` 的关键几栏（当前框架 / 失败集合 / 缺口 / 已排除的路径）
> 同时以**固定 schema 的 JSON 对象**存在，由 `scripts/state_patch.py` 读写。
> **每轮只读它，而不是读完全部历史再自己重建**——后者每轮的成本随历史增长，且重建本身会漂移。
>
> 补丁是**稀疏**的：只写变了的字段；**`null` 表示删除该键**。
> 这一条是这套东西里最要紧的——**让过时的前提从下一个读者眼里消失**，
> 而不是留在文里让每一轮重新判断"这条还算不算数"。
> 校验门保证：**没通过校验的补丁不生效**，但被拒绝这件事进审计日志。
>
> 为什么值得单独有一条：**`4.6` 要求缺口与它的趋势出现在同一个对象里**。
> 缺少这一层时，那个数会散在三份只增不减的文档里，4.6 永远开不了火。
> ⇒ schema、每个字段的正当性（**它让哪条规则开火**）、校验门、以及增量 Markdown 日志，
> 见 **`references/state.md`**。

> **硬规则 1.6：判据、用例、验收脚本也是被测对象。**
> 它们**不是你写的**——它们和你正在优化的东西一样，是外部给你的、可能本身有缺陷的实体。
> 所以第 0 天要**像读被测对象一样读它们**（这是 `1.3` 的推广）。
>
> | 读什么 | 问什么 |
> |---|---|
> | 用例生成器 | 它**保证**良态吗？哪些分支**没有**保证？ |
> | 判据内部 | 各项**量级自洽**吗？ |
> | 验收脚本 | 它的**计数**口径是什么？**命名约定**会不会让某些检查看不见？ |
> | 参考实现 / 精确解 | ★ 见下——这是最值钱的单个动作 |
>
> **★ 把"参考实现"或"精确解"当被测方，跑一遍同一道门。**
> 它过了 ⇒ 这道门至少**可满足**；它不过 ⇒ **这道门谁都过不了**，与你的实现无关。
> **这个动作不需要你的任何一行代码**，成本是一次运行。
> 没有它，"我们的核不准"与"这道门谁都过不了"**永远切不开**，你会用好几轮去修一个不可满足的门。
>
> 为什么要有这一条（2026-09-14，第二次独立战役）：
> 一次 1200 条的精度门报 **708 通过 / 492 失败**。三方比对后**真缺陷为 0**——
> 失败的 **96.5%** 来自用例构造（参考解自身是 `Inf/NaN`、某些档位无权条件数措施），
> 而判据本身**严了 256~400 倍**、**精确解自己都过不了**。
> ⇒ **整套规程此前假设"问题出在我自己身上"，而这次最贵的几个问题出在供给方。**

> **硬规则 1.4**：**每一条未验证假设，必须绑定一个已排期的证伪实验。**
> 只列进清单而不排期的假设，可以永远"以后再测"——**清单会变成一个只增不减的坟场。**
> ⇒ `TASK_ANCHOR` 的未验证假设表里，每行必须有：**怎么证伪** + **何时做**（第几轮 / 由什么触发）。
> 排不出期的，要么当场测掉，要么明确写下"接受它，不再计划验证"（那也是合法结论，但要显式）。

## 2. 证据台账 —— 对抗"自证偏差"

**硬规则 2.1：任何数字进入结论前，必须携带四要素。**

```
值 = 273.5        定义式：pmu / task_cyc
                  单位：事件数/周期（不是百分比！）
                  出处：tool/path.py:183
                  对比时还要写明：A 相对 B（哪一臂是哪一臂）
```

> **硬规则 2.2：对比数字必须带主语。**
> **禁止**写「+40 %」「快 3×」——它没有主语，可以在半年内被读反。
> **必须**写「**A 相对 B 慢 40 %**」或「**B 相对 A 快 3×**」。
> 本条来自一次真实事故：同一份测量被引用时把主语丢了，于是**支持某方案的证据被当成反对它的证据**，直接导致选错方向。

> **硬规则 2.3：不得引用自己的旧总结作为证据。**
> 引用任何历史数字前，**回到原始日志/原始 CSV/源码**重读一遍。
> 摘要会漂移，原始数据不会。

> **硬规则 2.4：量纲未核实的指标不算证据。**
> 先问三句：它的定义式是什么？单位是什么？**它可能超过 1 吗？**
> （若答案可能是"会"，那它就不是比例；把它当百分比用必然出错。）

> **硬规则 2.5：派生文档必须继承证据等级，不得升级。**
> 任何被复制进**复盘 / 失效目录 / skill / 摘要 / 汇报**的结论，必须**连同它的等级一起复制**。
> **手写的等级只有四种**：`已实测` / `已被独立复核` / `未受攻击` / `INVALID`（与 §7.2 一致）。
> **`未验证` 不是你手写的等级**——它是 lint 在"原始证据路径 `test -f` 失败"时**算出**的状态（§2.5.1 ②）。
> 派生文档**不得**把"未测"写成"已实测"，也不得省略"未受攻击"标记。
> 真实事故：本规程自己的失效目录曾把一次**从未执行**的实验写成「我方已实测：数值正确，但逐例平坦 **不足 1 %**」，
> 并附上一段量化的机制解释。**规程的第一个受害者是规程本身。**
>
> **2.5.1 机械检查（"要小心"不是一条规则）。** G1 的成因是**复制散文**。因此：
> 1. **建一份 `CLAIMS.jsonl` 台账**，每条结论一行、**带编号**：
>    `| id | 结论（一句话） | 等级 | 原始证据路径 | derived_from | valid_from | invalidated_at | invalidated_by | 记录人 |`
> 2. **派生文档引用编号，不复述散文**：写 `见 C-017`，而不是把 C-017 的内容再抄一遍。
> 3. **每次锚定（§1）跑一次 lint**，四条都能机械判定：
>    - 每条 ID 在台账里存在；
>    - **每条 ID 的"原始证据路径"实际存在**（`test -f`）；路径不存在 ⇒ 该条自动降级为 `未验证`；
>    - **派生文档里出现的等级 ≤ 台账里的等级**（允许降级复述，**禁止升级**）；
>    - **传递闭包**：若某条被 `invalidated`，则**所有 `derived_from` 链上包含它的条目必须也被标掉**
>      （见下方"依赖网络"）。
>
> 4. **四条已脚本化为 `scripts/claims_lint.py`**，并在实现中发现两条必须补的检查：
>    - **⑤ 无支撑断言**：既没有原始证据路径、也没有 `derived_from` ⇒ **ERROR**。
>      这正是某次探针 那种"从未被声明的隐含前提"（"探针真的跑了"）的形态。
>    - **⑥ `invalidated_by` 悬空**：指向了不存在的 id ⇒ ERROR。
>
> **重量控制（实操关键）**：**`derived_from` 只对"没有原始证据路径"的条目必填。**
> 有 `test -f` 得出来的证据 ⇒ 它是 base fact，`derived_from` 填 `—`。
> 于是**常见的"测量型结论"零额外负担**（绝大多数行），而**"既无证据又无推导来源"的那一行会被判 ERROR**——
> 也就是那次攻坚最贵的那次失效，被压成了一条可机械判定的规则。
> `valid_from` / `invalidated_at` / `invalidated_by` 只在写入与失效时才有值，平时留空，**不需要人工维护**。
> ⇒ **不要回填历史台账**；从下一个实验开始记。**回填是负担的来源，不是纪律的来源。**
>
> 一种等价物：`evidence/<gate>/<date>_<topic>/` 下的 REFUTED/MEASURED/PROMOTE 文档就是台账条目，
> 控制目录下的 `STATE.md` 与复盘是派生文档——**它们必须引用前者，而不是取代前者**。
> 一次 `grep -o 'C-[0-9]\+' 派生文档 | sort -u | while read id; do ... done` 就能跑完。

> ### 2.5.2 三条借自外部成熟方案的结构（2026-09-13 追加）
>
> 这三条补的正是"更正横幅"**做不到**的事：横幅是散文，**它不传播**。
> 真实事故：某次探针的假结论同时活在三处（`STATE.md`、失效目录、复盘），
> 因为那三处是**互不引用的副本，而不是一个依赖图上的三个节点**。
>
> **(a) 依赖网络（借自 TMS，Truth Maintenance System / 理由维护系统）**
> TMS 的核心不是"记结论"，而是**记结论的 justification**：它把 **base fact（前提，无需理由）**
> 与 **derived fact（推理结论，必须有理由）** 分开，并维护一张**依赖网络**——
> 每个节点的入边就是推导它的步骤。当某个前提被推翻，**以它为理由的结论全部自动失去支持**
> （dependency-directed backtracking）。它防的正是我们这次踩的坑：**撤回不传播**。
>
> ⇒ 落地：台账必须有 **`derived_from`** 列。追问每一行：**"这条结论，是哪几条别的结论推出来的？"**
> **其中哪一条其实是"没有理由、被直接当成前提"的？** —— 把隐式前提显式化。
> **真实事故的致命处**：那次探针 有一条**从未被声明的隐含前提**——"探针真的跑了"。
> 它不是一个结论，所以没人给它标等级，也没人检验它。**TMS 的纪律逼你把它写出来。**
>
> **(b) 双时间轴（借自时序知识图谱的生物时间模型，如 Zep/Graphiti）**
> 成熟方案区分**两条**时间轴：**事实何时为真**（valid time）与**记录何时被写入/失效**（transaction time）。
> 且其关键设计是：**旧事实被 `invalidated`，而不是被删除**——所以既能查"现在为真"，
> 也能查"某个历史时刻为真"。
>
> ⇒ 落地：台账加 **`valid_from` / `invalidated_at` / `invalidated_by`** 三列。
> `invalidated_by` 指向**推翻它的那条证据的 id**。**条目永不删除，只失效。**
> 这直接解决那次攻坚的两个问题：
> ① `created_at`（外部 artifact 何时可读）与"我们的结论何时开始依赖它"是**两条轴**，
> 用一条会让归因超出证据（§2.6）；
> ② 结论从写下到被撤回之间"一直有效"，而**没有任何字段记录它的失效时刻与原因**。
>
> **(c) 取代语义（借自 ADR，Architecture Decision Records）**
> ADR 的状态取值是 `proposed | rejected | accepted | deprecated | **superseded by ADR-0123**`——
> 注意它**不是**"已更新"，而是**一条指向新记录的引用**。**旧记录不编辑。**
>
> ⇒ 落地：把修正写成**新的台账条目**（`C-0yy`），旧条目状态改为 **`superseded by C-0yy`**，
> 而不是在旧文里加一段散文横幅。派生文档引用编号时会**自动跟随到最新**。
> 横幅仍可保留（给人看），但**判定依据必须是台账里的状态字段**。
>
> **边界（诚实声明）**：TMS 在 LLM agent 上**没有成熟的自动实现**——它要求 reasoner 显式产出
> justification，而 LLM 的推理不产生这种结构。**所以这里的三条都是"约定 + 人工登记 + lint"，
> 不是自动推理。** 外部方案给的是**记什么**，不是"自动帮你记"。
> 落地的重量全部压在 **lint 可机械判定**上——这也是为什么 2.5.1 的每一条都写成能跑的命令。

> **硬规则 2.5.3：任何在多处出现的量，必须有一处权威来源，其余处引用它。**
> 适用对象：**计数、行号、哈希、阈值、归因**——凡是被复制到第二处的量。
>
> **为什么它与 G1 同根**：G1 是"**散文**被复制后丢了证据等级"，
> 这条是"**数值**被复制后丢了同步"。两者都是**副本 vs 依赖图**的同一个病。
>
> **落地（两半都要，缺一不可）**：
>
> | 半 | 防什么 | 怎么做 |
> |---|---|---|
> | **① 单一权威来源** | **漂移**——两处都改了，但改成了**不同说法** | 值只写在**一处**（台账 / 源文档的一个字段），其余位置写成"见 X" |
> | **② 改完全仓 `grep` 旧值** | **残留**——漏改了某一处 | `grep -rn "<旧值>" .` **必须为空** |
>
> **为什么两半都要**：`grep` **防不了漂移**——两处都改过、但改成了不同的说法时，
> 旧值已经不存在，grep 全过，而两份文档已经不一致了。**那种只能靠"只有一处能写它"防住。**
>
> **更省事的形态：让量由权威处导出。** 例：本仓的"自检断言条数"出现在 README / CHANGELOG /
> 外部评审记录三处，但**权威是 `selfcheck.sh` 的实际输出**——三处与实测一致，
> 且**没有任何一处是"手工维护的"**。**这才是这条规则的正确落地：
> 不是"记得同步"，而是"只剩一个地方能写它"。**
>
> **两个真实实例（同一天内连续发生）**：
> 1. 一个跨十余个文件的仓里，把某个计数改了之后，批量替换**漏了一处**——
>    是"全仓 grep 残留"抓到的，不是靠回忆。**计数是最容易漂的一类量**，
>    因为它每改一次就要同步所有引用处。
> 2. 同一份事实（"某类失效的发现方式"）在**两份文档里漂移了**：
>    一份写"其余由归档校验发现"，另一份写"由外部审计发现"。
>    **归因也是会被复制的量**——而且它比计数更隐蔽，因为两句话读起来都通顺。

> **硬规则 2.5.4：每条结论必须随身携带它的作用域限定词。**
> 结论的强度**不得超过**产生它的证据所能覆盖的范围。写法上就是把限定词写进句子里：
> **"在什么条件下、对什么范围、由谁测的"**。
> 反例（都真实发生过）：把"**这条路径**没有余量"写成"**这个问题**没有余量"；
> 把"某次扫描**读到的**结构"写成"**这个算子**就是这么分档的"；
> 把"在我们跑过的那几个用例上"省略掉，读起来像"在所有用例上"。
> ⇒ **省略限定词不是简洁，是加息**——它让一条局部结论看起来像全局结论。

> **硬规则 2.5.5：每条载重结论必须附一条"重建命令"。**
> `test -f` 只证明**文件在**，不证明**结论能重算出来**。
> ⇒ 结论旁边写一条能**从原始数据重新得出它**的命令（或步骤），并确认那条命令跑得通。
> **判据**：把原始数据交给另一个人，他**只跑那一条命令**，能不能得到同一个数？
> 答不上来的结论，等级不能超过 `未受攻击`。

> **硬规则 2.6：引用外部实现前，先核验它的"可读时间窗"。**
> 在写下"我们早就该去读它、这是检索缺失"这类**因果归因**之前，先查该 artifact 的**创建时间**
> （PR/MR 的 `created_at`、commit 的 author/commit 日期）。
> 一个在你失败之后才出现的对手，**不能**被用来证明你"检索不力"。
> 真实事故：复盘把一次失败归因于"两三周没去读公开的同类实现"，
> 而该竞品 MR 的 `created_at` 距我们读到它只有 **数小时**——它在整个战役期间根本不存在。
> **归因强度不得超出时间线证据。**
>

> **硬规则 2.6.1：关于 artifact 的"存在 / 不存在"断言，必须写明你在哪个仓、哪个路径核验的。**
> 这类断言极易产生**假否定**：在错误的上下文里查一次，就会得到"它没了"，
> 而它会**直接改变计划**（"原样重测已不可能"⇒ 放弃重测）。
> 因此核验必须满足两条：
> 1. **在正确的仓/路径查**——在 `A` 仓 `git cat-file` 失败，只说明 `A` 仓没有这个对象，
>    **不说明上游删了它**；先确认那个对象**当初是被 fetch 进哪个仓的**；
> 2. **用"能否重新获取"来判生死，而不是用"我手上还有没有"**——
>    `git fetch <url> <ref>` 成功即存在（哪怕本地副本没了）；本地副本存在也不能反推上游还在。

> **补注（2026-09-14）：否定结论需要两个独立通道。**
> "我查了，没有"这句话的证据强度，**等于那条通道本身的探测能力**，不多一点。
> 通道若恰好对该形态失明（标题里的点号、大小写、非 ASCII、索引覆盖不到），
> 你会得到一个**假否定**——而它看起来与真否定**一模一样**。
> ⇒ **"换了几种查法"不构成证据，除非它们走的是不同的通道**
> （检索索引 / 通用搜索 / 直接取原物 / 问人）。
> **同一个 API 的五次调用，是一次。**
>
> 真实事故（2026-09-14）：核验者用 arXiv 检索查一篇标题含点号的论文，五种查法全 0 命中，
> 于是写下了"查不到"。**换一个通道，一次就命中**（arXiv `2608.26263`，accepted at EMNLP）。
> **一个假否定被当成结论写进了产物——而它是做核验的那个人写下的。**
> 写下"它已消失/已被回收"时，**必须附上你实际执行的命令与它所在的目录**。
> 真实事故（本条规则的来源）：一份更正横幅断言 artifact **已消失、重测已不可能**，
> 而三个"核查"没有一个有判别力：
> ① `git cat-file -t <sha>` **查的是本地对象库**——该 MR 头只被 fetch 进过临时目录，**从未进过大树**；
> ② `git ls-remote origin` 的 **`origin` 按设计就不带 MR ref**（空结果是预期的，不构成证据）；
> ③ 查的 `/tmp/<某外部实现的构建目录>/` 是一个**臆造路径**——而写该横幅的人**自己的文档里**记的构建目录是
> `<构建根>/外部实现`，**他连自己文档里的路径都没照它去查**。
> 实测结果三条全反：**该 commit 可全新 fetch 成功**、构建产物仍在且哈希未变、测量脚本仍在。
> **一次没有判别力的存在性检查，差点让一次完全可行的复测被当成不可能而放弃，
> 并被当作"确凿事实"写进了复盘、skill 与汇报。**
>
> **2.6.2（本条规则的推广）：比较两个数之前，先确认它们测的是同一件事。**
> 上面那次事故的**更正本身**又出了一次同物种的错：拿**打补丁后**的行号去比**打补丁前**的行号，
> 得出一个"偏了几行"的差值，于是发布了一条**假更正**——而两个数其实都对，只是参照物不同。
> ⇒ 同一个量在不同状态下（补丁前/后、不同 commit、不同构建、不同设备）**是不同的量**。
> 写"更正"之前，先回答：**我这两个数，是在同一个参照物上取的吗？**

> **硬规则 2.6.3：任何写进结论的"外部数字"，必须当场核验，并记下核验方式。**
> 对象包括：某个仓库的 star 数、某篇论文的存在与出处、某个实现的加速倍数、某个基准的成绩。
> **"核验方式"指你实际跑过的那条命令、或实际打开过的那个页面**，不是"我记得"。
> 未核验的，写成"未核验"，**不得因为它看起来合理就当作事实使用**（§2 举证责任）。
>
> 真实事故（2026-09-14）：一份调研给出十余条这类数字，
> 其中**"某仓库 0 star 却被推荐为生产级"由读者手工抓到**，随即推荐被换成另外两个"5.3k star"的仓库——
> **而换的时候没有引入任何新证据**。
> 事后核验：那些 star 数**确实属实**（连带我自己对其中一条的怀疑，也是错的）；
> 而**我在核验时写下的"那篇论文在 arXiv 上换五种查法都查不到"，是错的**——
> 五种查法全走**同一个通道**（arXiv 检索接口，对标题里的点号失明）。
> 换一个通道，一次就命中：arXiv **2608.26263**，"SKILL.state: Scalable Long-Horizon Agent Skills"，
> Comments 一栏写着 `accepted at EMNLP`。**同一个通道的五次调用 = 一次。**
> ⇒ 三个失效同时存在：**数字未经核验**（本条）、**改口不是由证据驱动的**（§8.1）、
> 以及**拿一个通道的失败去下否定结论**（§2.6.1 补注）——**最后这一条是核验者自己犯的。**
>
> **与本仓"从源生成清单"是同一件事**：你要引用的是**你打开过的那个页面**，
> 不是**你以为它在的那个页面**。

> **硬规则 2.7：读到起决定作用的外部 artifact，当场落盘进自己的 evidence 树。**
> **外部 artifact 的可读窗口是窄的，而且会关闭**——它在冲线前可能尚未存在（验收后才公开），
> 在你读过之后也可能被删除、force-push、或所在仓被回收。
> 凡**起决定作用**的外部 artifact（竞品提交、兄弟算子、上游参考实现、MR head 的树），
> **读到的那一刻**就执行，成本一次 `cp` + 一次 `sha256sum`：
>
> **完整闭环（缺任何一环，结论都会在下一次 `git gc` / 仓回收后变成不可复核）：**
> ```
> ① 读到   →  ② 落盘（源文件 + 二进制复制进 evidence/<gate>/<date>_<topic>/external/）
>          →  ③ 记哈希（sha256sum + 记录 commit / ref / 获取命令与 URL）
>          →  ④ 台账登记（CLAIMS.jsonl 一行：id / 结论 / 等级 / 原始证据路径）
>          →  ⑤ lint 时 test -f 校验（§2.5.1：路径不存在 ⇒ 该条自动降级 未验证）
> ```
> **判据（§6.2 同款）：「这条信源，一周后还拿得到吗？」拿不到的，读到当场归档。**
> 真实事故：那次攻坚读了竞品 MR 却**只留了摘要**，源文件与二进制都未落盘 ⇒
> 一组对外的对照读数**一度只能降级为 `未验证`**，因为没有可追溯的原始出处。
> **后续（2026-09-13 晚）**：该结论后来**靠一次配对复测救回来了**——A/B/A2 背靠背 + 精度门先行 +
> stdout 入档，5 例读数全部在 1 % 内复现，等级升回 `已实测`，竞品源码与二进制也已补做落盘归档。
> **但这次能救回是运气**：被测对象恰好还在（同一份二进制、哈希未变）。
> **若当初执行了闭环的第 ② 步，就根本不需要"救"。**
> ⇒ 这条规则的重量不在"会不会丢"，而在**"丢了以后你还得再花一整轮去补，且未必补得回来"**。

## 3. 装置门 —— 探针生效性与门的语义

> **本节是唯一能拦住"装置失效"的环节。** 常规纪律抓不住它：
> 预注册抓不住（预测可以照写）、A/B/A 对照抓不住（见 3.3）、精度门抓不住（见 3.4）、
> 独立复核**也不一定**抓得住（复核者读的是同一份假数据）。
> 它需要的不是"更好的测量纪律"，而是**对装置本身的、与测量无关的检查**。

> **硬规则 3.0（判别力检验 —— 本节所有条目的共同根）**：
> **任何检查、探针、编码、指标或"验证"，先问一句：
> "如果我要找的东西**存在 / 生效 / 发生了**，我这个检查**会不会**变绿（或变红）？"**
> 答不上来，**这个检查就没有判别力，它给出的任何读数都不是证据。**
>
> **更尖锐、更好用的问法（推荐）**：
> **「在最坏的情况下——它没跑、它不存在、它失败了——我这个检查的输出，
> 会不会和成功时一模一样？」** 会 ⇒ 判别力为零。
>
> 判别力的缺失有四种典型形态，那次攻坚各发生过：
> - **探针够不着**（E1：分支在无条件 `return` 之后 ⇒ 两臂跑同一份代码）；
> - **编码分不开**（E3：`(true,≈0)` 与 `(false,≈1000)` 编成同一个整数 ⇒ 两次相反结论都"有据"）；
> - **检查跑在它不可能成功的地方**（E6：在从未 fetch 过该 MR 的仓里 `git cat-file`；
>   用 `git for-each-ref` / `ls-remote origin` 去查一个**按设计只写 `FETCH_HEAD`、不建本地引用**的 fetch）；
> - **读数不可区分**（E7：`grep -c '^\[  FAILED  \]'` 对**空日志（没跑）**与**跑了且全过**给同一个 `0`
>   ⇒ 一次**根本没执行**的精度门被读成了绿灯）。
>
> **判别力检验是"零成本"的——它只是一句话。** 而它拦住的四次事故，代价合计是整条路由
> + 一份差点永久无法复核的结论 + 一次差点放弃的复测 + 一次假绿灯。
> 反过来说：**一个永远返回"不存在""无差异""平""0 个失败"的检查，
> 必须先被证明它能返回"存在""有差异""动了""真的跑了"。**
> ⇒ 最省事的落地形式：**给每个"计数/枚举"型检查配一个"确实跑了"的计数器**
> （`grep -c '^\[ RUN \]'`），**`ran == 0` ⇒ 判 `INVALID`，不得判 `PASS`**。

> **硬规则 3.0.1：任何汇总行必须携带分母。**
> `pass=k` 若不同时给出 `total`，则 **`total=0`（一个都没跑）与 `total=k`（全跑且全过）不可区分**
> ——这与 E7 是同一个物种，只是发生在**汇总层**而不是明细层。
> ⇒ 所有汇总输出写成 `pass=k / total=n`，并在 `n==0` 时显式报警。

> **硬规则 3.0.2：每一条写进协议的判据，必须随交付一份"已知应当报错"的阴性样本。**
> 即：**拿一个你确定它该开火的输入跑一遍，确认它确实开火了。**
> 现在只有本仓的三个工具（两个 bash 脚本 + 一个 Python 工具）有这种待遇；**验收判据自己、runner 的通过规则、收尾判据，一个都没有。**
> ⇒ 没有阴性样本的判据，其绿灯**不构成证据**——它可能只是在返回一个常量。
>
> 一句话记法：**判据也要交付它自己的"该开火却没开火"的样本。**
> （这条是"你自己写的东西也受同一套规则约束"在判据上的形态。）

> **硬规则 3.0.3：每条判据要两个样本，不是一个。**
> `3.0.2` 要求"已知应当报错"的阴性样本——**那只是一半**。
> 还必须有一个**"已知应当通过"的阳性样本**。
>
> **为什么**：为增加判别力而加的检查，会**新增假红**。
> 真实事故（2026-09-14）：为防"空统计假绿"，给判据加了一条 `validCount > 0`；
> 而它在**输出与参考逐位相等**时也开火（有效位数为 0 是合法情形）——
> 于是一个**逐位正确**的内核被判失败，**一次产出 134 个假红**。
> ⇒ **只补"应报错"的样本，会把判据从假绿推向假红**，而假红更贵：
> 它会让你去修一个根本没坏的东西。
>
> **判据**：一条判据上线前，两个样本都要跑过——
> **已知正确答案 ⇒ 必须通过；已知错误答案 ⇒ 必须报错。**
> 只有前者，它可能是个常量；只有后者，它可能在惩罚正确。

> **硬规则 3.1：探针在证明自己生效之前，不算证据。**
> 任何 routed / gated / env-gated 探针，**在读取任何数字之前**，必须完成下列四项中的**至少一项**，
> 并把证据写进实验记录：
>
> **⇒ 方法①已脚本化：`scripts/probe_liveness.sh`（退出码 0/1/2）。**
> **它必须先在已知答案上通过验收**：拿一个你自己**知道分支不可达**的探针跑，
> 它必须报 INVALID 并指出那条更早的 `return` 的行号。跑不出这个结果，脚本就是装饰品。
> （本规程的脚本就是这样验收的：拿一次真实事故的补丁跑，它报 `INVALID`，并指出
> 某个**更早的无条件 `return`**（连同行号）被一条守卫完全覆盖——而那条守卫在源码里
> 写成了一个 `bool` 别名，脚本要先把它解析回真条件才判得出来。
> **脚本的四个自身缺陷就是这样被测出来的**。）

| # | 方法 | 具体做法 | 成本 |
|---|---|---|---|
| 1 | **结构**：证明分支对**目标输入**可达 | **跑 `scripts/probe_liveness.sh`**。它做三件事：① 抽出函数体、检测插入点前**所有 `return` 及其守卫**（含多行 `if` 条件与 `bool X = (…)` 别名解析）；② 若某守卫的谓词集**被目标输入完全覆盖** ⇒ 直接 `INVALID` 并打印守卫原文+行号；③ 打印 ②③④ 的确切命令 | **一次运行** |
| 2 | **行为·廉价**：让探针产生可观测副作用 | 在探针分支内加 `fprintf(stderr, "[PROBE-FIRED] n=%d batch=%u\n", n, batchSize);`，跑一个目标用例，`2>&1 \| grep PROBE-FIRED` | 一次构建 + 一次单例运行 |
| 3 | **行为·决定性**：确认启动的内核就是探针所选的那个 | <profiler> 采集一个目标用例，读其**内核名清单**并做直方图（具体命令属领域层）；探针臂应出现探针所选内核（如 `<probe_kernel>`），对照臂应是生产内核（`<prod_kernel>`） | 一次采集（工具链已具备） |
| 4 | **差分·零成本**：找一个**只有新路径能影响**的用例，证明它动了 | 若探针改变了路由/分桶，去找**唯一能命中新桶**的用例，看它是否移动（哪怕位移很小）。**若找不到这样的用例，说明探针的作用域与用例集不相交——这本身就是警报。** | **零**（不需要额外构建或采集） |

> **硬规则 3.2（结构差异推论）**：**若两臂的实测差异，小于两臂实现的"结构差异"，先怀疑探针，不要相信结果。**
> "结构差异"指：线程数、片上预算、启动次数、数据布局、执行单元。
> 两个在这些维度上完全不同的实现**不可能**打平到 1 % 以内——打平意味着它们**是同一份代码**。
> 真实事故：两个在**线程数、每块矩阵数、启动次数**三个维度上全都不同的实现（一个线程式、一个向量式），两臂只差 **不足 1 %**，
> 而这被读成了"改动中立"而不是"改动没发生"。

> **硬规则 3.3**：**对照臂检验的是可复现性，不是有效性。**
> A / A2 逐例一致**只**证明测量可复现；**一份死探针完美可复现**。
> 因此 A/A2 一致**不能**用作探针生效的证据。

> **硬规则 3.4（门语义）**：**绿灯证明的是"所走路径正确"，不是"走的是哪条路径"。**
> - **精度门**通过 ⇒ 被执行的代码算对了；它**不**说明被执行的是探针那条分支。
> - **性能门**通过**不校验数值**。⇒ **一个"做更少工作"的改动会产生惊人的假加速，并让整条带**全部通过**。**
>   真实事故：把一个小尺寸用例重路由到一个**算错**的内核，得到 **一个数量级的假加速**、
>   整带**全部通过**——而精度门一开就 FAILED（3 例）。**量级是唯一报警的东西**，
>   而量级恰恰也是真突破会有的东西。

> **硬规则 3.5（工作减少型探针）**：凡机制是"**做更少的工作**"的探针
> （提前退出、缩小覆盖、跳过列、降低精度、遗漏区域的 tiling），
> **必须在预注册里声明这一点，并无条件先过精度门再看性能**。
> 便宜的合理性上界：**"这会不会让我们比一个已知能通过的实现还快得多？"** 会 ⇒ 先去找丢了什么工作。

> **硬规则 3.6（无生效证据不得判 refuted）**：证明不了探针生效时，结论只能记 **`INVALID`**，
> **不得**记 `refuted`。一个"无效结果"与一次"失败实验"在计数上完全不同：
> `INVALID` 不进 §4 的失败计数（那次实验没发生），但**必须**进 §7 的自我否证清单。

> **硬规则 3.7**：**四条方法里，④（差分）应优先试**——它是唯一**零成本**的一条
> （不构建、不采集、不占设备），而且那次攻坚真的用它自证过 live。
> 只有在找不到这样的用例时才退到 ② / ③。

## 4. 失败计数按"架构"归并 —— 对抗"在错误架构里刷实验"

每个失败实验必须归类：

| 类别 | 含义 | 例 |
|---|---|---|
| **战术失败** | 表述/架构不变，只换参数或微结构 | 改车道划分、改同步、换 FMA、调 tile 大小 |
| **架构失败** | 换掉求解这个形状的**表述或家族** | 从 SIMT 换成 SIMD、从通用路径换成专用家族、换执行单元 |

> **硬规则 3.7：并发下，「设备空闲」不是互斥判据——锁才是。**
> 多个写者并行时，**"我检查的那一刻它是空闲的"证明不了"我用它的那段时间它是空闲的"**。
> 两者的差别，就是"没有互斥"与"有互斥"的差别。
>
> - **锁是唯一的互斥判据。** 占用检查（进程表 / `npu-smi` / 工作树状态）
>   只能用来**发现陈旧锁**，**不许用它绕过锁**——它证明不了未来。
> - **锁要能表达「谁持有、何时到期」**，否则一个人死了整条线就停了。
> - **短任务不排在长任务后面**：按锁排队时，排在长任务后面的短任务，
>   有效等待等于长任务的全部时长——那会让"我排上了"变成一句空话。
>
> 真实代价（2026-09-14，第二次战役，四条并行线）：
> **一次真实撞车**（两个写者同时占设备，该次测量作废）、
> **一次协议写反**（把"用占用检查判断能否开工"写进了协议）、**一次排期倒置**。

> **硬规则 4.1 / 4.2 〔标定阈值，非推导值〕**
> 原文是：**「3 次战术失败 = 1 次架构失败」「累计 2 次架构失败 ⇒ 禁止再开实验」**。
>
> **⚠️ 这两条的数字（3 和 2）是标定值，不是推导出来的。** 在一份以"每条规则都要能追到具体损失"
> 为收录标准的规程里，它们**追不到**——它们追到的是"三次差不多够了"。所以在此明确标注，
> 免得后来人以为它们可以被推理出来，从而不再去问它是否适用于自己的任务。
> **（这与本规程对别人的要求是同一条：把标定值伪装成推导值，就是在制造手调表。）**
>
> **⚠️ 而且实测证明它们不触发**：一整条路径上的连续实验全部落在同一架构内时，
> 按 4.1 归并**只累计到 1 次**框架失败，4.2 的阈值**始终没有触发**。
>
> **⇒ 判定权归 4.3，不归这两条。** 它们保留下来只作为"早就该停下来看看"的粗启发。
> **正确的问题是「失败集合动了吗」，不是「累计到 2 次了吗」。**

> **硬规则 4.3（停滞触发器 —— 比 4.1 更强，优先用；判定以本条为准）**：
> **失败集合本身是否移动，比"做了几个实验"更能判定架构是否有效。**
> 若**同一组失败用例连续 3 轮实验后仍未移动**（名字逐一对得上、缺口未缩小），
> **计为 1 次框架失败**，无论这几轮实验在技术上"失败"还是"成功"。
>
> 真实事故：**7 个实验全部落在同一架构内**，计数上看是"7 次失败、早已该停"，
> 但按架构归并只是 **1 次**——而规则当时按实验计数，反而让人以为"再试一个就好"。
> 更糟的是：即便改按"3 战术 = 1 架构"归并，那次攻坚也只有 **1 次架构失败**，
> `4.2`（累计 2 次）**仍然不会触发**。**只有 4.3 会在这一次触发**——因为那两个用例的名字从头到尾没变过。
>
> ⇒ **教训：按"架构"归并还不够，必须按"失败集合是否移动"归并。**
>
> **⚠️ 但"移动"有两个含义，别混（2026-09-14 补）：**
> **成员变化**（哪几个用例还在失败集合里）与**缺口缩小**（同一个用例还差多少）。
> **只有成员变化才算"换了问题"。**"每轮都缩一点"**不是**移动——
> 那种形态由下面的 4.6 接住，本条对它**不会开火**。
>
> **硬规则 4.6（进展的量级外推 —— 唯一不依赖"自我怀疑"的换框架触发器）**：
> **每次抄失败集合时，同时抄下缺口（还差多少）。**
> 然后做一次**纯算术**：按最近 k 轮的平均缩小量外推，**在剩余轮数预算内到得了目标吗？**
> 到不了 ⇒ **这条路径在预算内不可达**——这与"它还能再快一点"无关。
>
> **为什么必须有这一条**：最危险的失效形态不是"反复失败"，
> 而是**失败集合在动、每轮只动一点点**：每轮都"有进展"，每份复盘都写得诚实，
> 每个数字都对，**而算术上它永远到不了**。
> **"看似次次有进展"不是运气不好，是一个可以提前算出来的结论。**
>
> **它为什么不可替代**：4.3 与 §5 都要求你**先意识到**自己在错的路径上，
> 而"框架锁死"的定义就是**你意识不到**。量级外推只需要一个你**本来就在测**的量——
> 所以它是这套规程里**唯一一条不需要先自我怀疑就能开火**的换框架触发器。
>
> **硬规则 4.4**：**每次实验后，抄下此刻的失败集合（用例名逐一列出）。**
> **硬规则 4.5（开跑之前先写）**：**每个实验动手之前，先写下"如果这个改动有效，失败集合会怎么变"**——
> 哪几个用例应当从失败集合里消失、缺口应当缩小到多少。
> **把信息量的判定提前到开跑之前**：一个改动如果**无论成败都不会让失败集合发生可区分的变化**，
> 那它**开跑前就已经不产生信息**，不必去跑。
> 计数与判定的依据是**失败集合的移动**，不是实验清单。
> 没有逐例失败集合的记录，4.3 无法执行。

## 5. 耗尽触发器 —— 对抗"把路径的极限读成问题的极限"

当一条路径**同时**满足：

1. **忙管 > 95%**（如 `向量管占用率 ≥ 0.95`）；**且**
2. **算出的工作已经到了算法下界**——这一条**不是"我写下过下界"**，
   而是"**实现实际发出的工作 == 算法的最小值**"；**且**

> **⚠️ 这一条最容易被读松（2026-09-14 补）。**
> 写下 `n³/3` 只完成了**算法侧**的一半。必须再给出**实现侧**的同一个量：
> **实际发出的指令数（或等价的向量操作数）÷ 算法最小值 = ？**
> - 比值 ≈ 1 ⇒ **这一族到地板了**，这是"换家族"的充分理由；
> - 比值 ≫ 1 ⇒ **存在未记账的差**，那么"我试过的都失败了"**推不出"这一族到地板了"**——
>   它只说明**已试的那些机制**不成立。
>
> 真实事故（2026-09-14）：一条路由以"向量管 99.8% + 结构项逐项排除 + 算法是 `n³/3`"
> 被判 `BLOCKED`，七条机制闭合，记录里**只有消除、没有下界**。
> 而同一形状、同一硬件上，一个外部实现通过了全部用例
> ⇒ **"七次否定"被当成了"这一族不可能"，而它们是两件事。**
3. **结构项已全部排除**（访存冲突、车道利用、同步、竞争、调度——逐项有实测或推导）

> **硬规则 5.1：三条同时成立 ⇒ 禁止再对该路径做微杠杆实验。**
> 下一步**只能**是：(i) 换表述/换家族，或 (ii) **去读别人怎么解这个形状**（见 §6）。

> **硬规则 5.2：在记录里写下这句话，并保持它在场：**
> **「这条路径已耗尽」≠「这个问题不可解」。**
> 两者差一个动作——**换形状**。混淆它们会让整个战役停在一个可达成的目标前。
>
> 真实事故：三条条件早已同时成立并被正确测出，结论却写成了"没有杠杆了 ⇒ 大概是形成层极限"，
> 而正确推论是"这条路径没有余量 ⇒ 该换形状"。此后又做了 4 轮微杠杆实验，全部被否。
> **注意 5.1 的措辞是"禁止微杠杆"，不是"禁止实验"**——照它执行的动作是**去写一个为该形状定尺寸的新内核**，
> 而不是再做一个改参数的变体。

> **硬规则 5.3：`blocked` 是一个状态，不是一个决定。**
> 一条路径被判 `blocked` 之后，**它并没有结束**——它只是不再消耗预算。
> 要真正**终止**它，必须同时交出三样：
>
> | 交出什么 | 不交会怎样 |
> |---|---|
> | **① 重启条件**：什么新证据会让它重新值得试 | 它以「以后可能还要看」的名义**永远占着注意力** |
> | **② 接手路径**：剩下的目标由谁走 | 目标悬空，而所有人都以为有人在管 |
> | **③ 移交对象**：谁做的这个决定、交给谁 | **没有人有权宣布终止**，于是它既不能继续、也没真正让位 |
>
> **三样缺一，那条路径就会一直挂在账上**——而挂着的路径与正在走的路径**争的是同一份注意力**。
>
> **跨会话时，这三样就是交接物。** 下一个会话接手时先读它们，
> 而不是先读你的总结（硬规则 `2.3`：总结会漂，它们不会）。
>
> 真实形态（2026-09-14）：一份 `BLOCKED` 记录写得很完整——七条机制逐条闭合、
> 每条都有实测或两路推导、连「什么会改变答案」都列了。
> **但它没有被终止**：没有重启条件、没有接手路径、也没有移交给谁。
> ⇒ **「我试完了」与「这条路走不通」是两个结论。** 前者你可以自己下；
> **后者需要有人签字**，而那个签字动作就是这份交接。
> **没有它，`blocked` 只是一个更好听的「在办」。**

## 6. 对标 —— 对抗"只在自己的树里找答案"

> **前提事实（来自用户，那次攻坚之外的一般规律）：**
> **竞品的实现在你冲线之前通常不可得。** 交付物常在**通过验收之后**才公开；
> 一个竞品 PR 在你最需要它的那几周里，很可能**还不存在**。
> 因此"对标"**不是**"去找竞品"，而是**按可得性从近到远地找已知能通过的安排**。

> **硬规则 6.1（元规则）：任何计划的关键路径，不得经过"一个可能不存在的外部 artifact"。**
> 写下"只要去读某份外部实现就能拿到答案"之前，先问：
> **它现在是可读的吗？如果它在我冲线时才出现，我的计划还剩什么？**
> 真实事故：复盘把整场失败归因于"没去读对手的设计，读它只要半小时"，
> 而那份竞品 MR 的 `created_at` 距我们读到它只有 **数小时**——
> 它在整个战役期间不存在。**把胜负押在一个当时尚未创建的 artifact 上，是设计缺陷，不是运气不好。**

> **硬规则 6.2：按可得性排序的信源优先级。**
> 两个强制时点：**(a) 任务开始第 0 天**；**(b) 第一个用例失败时**（不是第一个实验失败时，是**第一个用例失败时**）。
> 每个时点按下列顺序做，**做到哪一层有结论就停**：

| 优先级 | 信源 | 为什么在这个位置 | 示例 |
|---|---|---|---|
| **①** | **同仓 / 同上游的兄弟算子** | **已经在你手上的树里，且已被验收**——零检索成本、零可得性风险 | 一个同形状段的兄弟算子，已通过验收——**它就在你的树里** |
| **②** | **相邻形状段你自己的 A/B**（尤其"邻带用了另一种表述"的那种） | 你自己跑过、有原始日志、**证据等级最高** | `<内部实验记录>`：邻带（一段连续尺寸区间）的 **SIMD vs SIMT** 对照 ⇒ 「A 相对 B 慢 <数值>」（写法见 §2.2） |
| **③** | 上游参考库 / 公开文档 / 硬件白皮书 | 通常长期可读、稳定 | 官方文档、同族参考实现 |
| **④** | **竞品提交** | **通常在你需要它时不存在**；且它只给"结果"，不给"为什么" | 同期一份外部实现（攻坚期间尚未创建） |

> **④ 明写：不得放入关键路径。** 它可以在**出现之后**用来验证或定位差距（如那次攻坚用它把缺口
> 从一个"这就是路径极限"的结论改写为一个**有量级的实现差距**），但**不得**作为"我该怎么办"的唯一或主要来源。

> **选择信源时的判据（对 ①–④ 每一层都问一遍）：**
> **「这条信源，一周后还拿得到吗？」** 拿不到的——**读到当场归档**（§2.7 的五步闭环）。
> ① 和 ② 之所以排在前面，正是因为这个问题的答案分别是"是"（在我自己的仓里）
> 和"是"（我自己跑的证据）；④ 的答案通常是"不一定"。
> MR 的 head 是 `refs/merge-requests/N/head` 这种**他人可随时删除或 force-push 的引用**，
> 不具持久性保证——**这不是假想风险，是这个信源类型的固有属性。**

对标时只问三件事：

1. 这个**形状**（n 的范围、batch、数据布局）它**交给谁算**？
2. 它的**分档**是怎么定的——**推导**出来的还是**拍**出来的？
3. 它对**我正在失败的那个点**怎么处理？

> **硬规则 6.3（★主条）：邻居的存在性证明就是证据。**
> **当同族算子（①）或相邻形状段（②）在同一硬件上已经用另一种表述/家族通过时，
> "它不适用于我"必须有证据，否则它是一条未验证假设**，必须进 `TASK_ANCHOR` 第 5 节。
>
> 那次攻坚同时握着 ① 和 ②，**两个都读了，两个都没当成证据**：
> - **①**：一次上游扫描（百余个 MR）读到了 `一个兄弟算子`——**一个 全部通过 的兄弟算子，
>   它把**整段相邻尺寸**交给了另一种执行安排**——被一句"不同算子，不适用"打发；
> - **②**：**自己跑的**邻带 A/B 对照**写着「**A 相对 B 慢 40 %**」，
>   而我们这边**那个尺寸段正跑在另一种模型上**——这个数字被**读反**成了"另一种方案动机薄弱"（见失效目录 B5）。
>
> **而最终取胜的方式，正是"为那个小尺寸段写一个向量家族"。**
> ⇒ **不要用"表述不同"解释掉一个邻居的存在性证明——那正是它的价值所在。**
> 一个 ①/② 级的邻居证明，**证据等级高于任何 ④ 级竞品**，因为它在你的树里、可复查、且已被验收。

> **硬规则 6.4：分档应当是推导的。**
> 优先让阈值由**容量/位宽约束算出来**（并写成 `static_assert` 让编译器守），
> 而不是手调常数表。**手调表是技术债**：它让所有人都不敢动架构，
> 于是所有努力自然流向"在旧路径上调优"。
> （校准：竞品自己的注释里也承认这一点——**预算来自已验证的实现，而不是查询硬件上限**，
> 所以准确说法是"**顶层切点由硬件常量导出、预算不变量靠推导+标定**"，不是"全部推导"。）

> **硬规则 6.5**：对标得到的**数字**同样要过 §2 与 §3：写明**哪一臂是哪一臂**，
> 并确认测的是**你的**用例与阈值（做法：只换被测库的 `LD_LIBRARY_PATH`，其余 runner / 用例 / 阈值全不变）。

## 7. 自我否证义务 —— 对抗"无法否定自己前面的结论"

> **硬规则 7.1：每次重新锚定（§1）必须包含一节：**
> **「我现在最不确定的旧结论是哪一条，什么证据能推翻它？」**
> 写不出来，说明没有再检验；不是"没有问题"。

> **硬规则 7.2：结论的状态标签只有四种：`已实测` / `已被独立复核` / `未受攻击` / `INVALID`。**
> 自己写下的、没人挑战过的结论，只能标 **`未受攻击`**——**不得**标 `verified`。
> 证明不了装置生效的，标 **`INVALID`**（见 3.6），**不得**标 `refuted`。

> **硬规则 7.3：新证据推翻旧结论时，去改那份旧文档，加更正横幅。**
> 禁止静默取代。**改变主意是交付物**，要被记录、被计数，而不是被抹平。
> （一份"从未改变过立场"的长战役记录，几乎必然是没在检验。）
> **并检查派生文档**（skill / 目录 / 摘要）是否复制了那条被推翻的结论——见 2.5。

## 8. 独立审计（强制）—— 本规程中经验收益最高的一条

> **硬规则 8.1：主攻手不得自审。必须有一个独立上下文（subagent / 另一个会话）承担审计。**
> **推论：不得因压力而改口。** 推翻一条结论的必须是**新证据**，不是提问者的语气。
> 真实事故（2026-09-14）：被指出"那个仓库 0 star"之后，推荐**直接被换掉**，而**没有引入任何新的核验**。
> ⇒ **改口与坚持都必须是证据驱动的**。一个"只在被质疑时才改、且改的依据是对方不满意"的评审，
> **它的绿灯与红灯都没有信息**——它返回的是提问者的情绪，不是世界的状态。
> 与「从不撤回」是同一个病的两面——见本节「审计者的职责」里那条
> **必须报告自己撤回了什么**。

来自真实统计：某战役中**全部 5 处数字/证据误用、以及 1 处方向读反，都是由第二双眼睛看原始数据发现的，零次由主攻手自己推理发现。**
（同战役另有一处装置失效，是主攻手自己回读控制流发现的——**这不削弱本规则**：
审计者按同一份清单会把那次检查**制度化**，而不是依赖偶然。）

审计者的职责（角色定义见 `agents/long-horizon-auditor/AGENT.md`）：

- **只读原始数据**（原始 CSV、原始日志、源码），**不读主攻手的总结**；
- 有权也有义务**否证**主攻手的结论，并**主动去找反例**；
- **必须报告自己撤回了什么**（一个从不撤回的审计者等于没有审计）；
- 对"对比类结论"逐个检查**主语是否齐全**（§2 硬规则 2.2）；
- **对每个"改动无效/被否"的结论，先查探针是否被证明生效**（§3 硬规则 3.1）；
- **查探针臂是否可能"做更少的工作"**，若是，检查它是否先过了精度门（§3 硬规则 3.5）；
- **抽查台账的 `derived_from` 是否完备**（§2.5.1 ⑤）：**每条"既无原始证据路径、又无 `derived_from`"的条目
  都是一个未声明的隐含前提**——那次攻坚最贵的那次失效就是这种形态（"探针真的跑了"）。
  并检查**失效是否真的传播**（§2.5.1 ④ 闭包）：被推翻的条目，其下游是否也标掉了。
  这两条都可运行 `scripts/claims_lint.py` 判定，**不要靠读**。

## 9. 完成判据 —— 对抗"用代理指标宣布完成"

> **硬规则 9.1：宣布完成时，必须逐字重述验收判据，并给出实测值对判据的比对。**
> 区分三句话：**"已达成"** / **"接近"** / **"当前站位是 X，未达成"**。
> 只有第一句能用于宣布完成。

> **硬规则 9.2：若判据本身受噪声影响（例如判定量是均值而设备会偶发离群），
> 必须在**冲线之前**写下收尾判据**并经决策者批准**——不得在最后一步临时商量。
> 且**不得**以任何方式放宽验收语义；只允许不改变宽严的**估计量**改进（如抗离群统计量），
> 且必须证明它对**已知的真实失败**不产生翻转。

> **硬规则 9.3**：**任何"通过数很高"的中间结果，都不等于正确。** 见 3.4。
> 宣布"接近"之前，确认你的通过数是**在一个数值正确的内核**上取得的。

## 10. 每轮实验的最小闭环（贴在墙上）

```
1. 假设（可证伪、写下来）
2. 预注册：预期值 + 什么结果算否证 + 若机制是"做更少的工作"则声明
3. 检查设备/树/二进制/锁
4. ★ 装置门：证明探针生效（`scripts/probe_liveness.sh` 判结构；或廉价行为 / 内核名 / 差分用例），证据入档
5. 精度门 → 性能门（顺序不可换；工作减少型探针尤其）
6. 配对或对照测量（不接受单次无对照；记住对照只证可复现）
7. 结论五选一：promote / refute / inconclusive / blocked / ★ INVALID
8. 失败先归档再回退；归档后立刻 `wc -c` 校验 patch/stat 非空，不留未归档临时树
9. 抄下此刻的失败集合（逐例列名），更新 §4 计数
10. ★ 提交状态补丁：`state_patch.py --state <state.json> --log <EVENTS.md> --patch <p.json>`
    （只写变了的字段；`null` 删除；`gap_now_pct` 让工具自动追加这一轮的趋势）
    —— **校验门拒绝时状态不动，去读拒绝原因，不要绕过它**
11. 更新台账与锚定；若触发 §4 / §5 / §6，立刻执行强制动作
```

> **第 4 步与第 8 步是本规程最新增补的两步**，也是本规程诞生后**第一件**真实事故（那次探针）
> 与更早一件被侥幸救回的事故（归档写出 0 字节 patch）分别对应的两步。

- `scripts/probe_liveness.sh` — **装置门 §3 方法①的结构检查（可执行）**。
  用法：`probe_liveness.sh --src <host.cpp> --func <入口函数> --probe <探针标记> --target <谓词> [--target …]`。
  退出码 `0`=未发现拦截 / `1`=**INVALID**（探针不可达）/ `2`=无法判定。
  **它自己必须先通过验收**：拿一个你知道分支不可达的探针跑，必须报 INVALID 并指出那条更早的 `return`。
  （验收样本：拿一个已知不可达的探针补丁跑，必须报 INVALID 并指出那条更早的 `return`。）
- `scripts/claims_lint.py` — **§2.5.1 台账 lint（可执行）**。
  用法：`claims_lint.py --ledger <CLAIMS.jsonl> [--root <仓库根>] [--doc <派生文档>]... [--strict]`。
  退出码 `0`=全过 / `1`=有 ERROR / `2`=无法判定。六条检查：① id 唯一合法 ② 证据路径 `test -f`
  ③ 派生文档不得升级等级、不得引用不存在的 id **④ 失效的传递闭包** ⑤ **无支撑断言** ⑥ `invalidated_by` 悬空。
  **它自己已通过夹具验收**（正/负/破损三向对照）——验收样本里那一份"破损台账"同时复现了
  **G1（撤回不传播）** 与 **某次探针的隐含前提（无支撑断言）**。
- `references/failure-catalog.md` — 真实事故目录（每个失效模式的**具体实例**，含数字与出处）
- `references/anchor-template.md` — `TASK_ANCHOR.md` 填写模板
- **`references/asset-index.md` — ★ 入口：场景路由 / 失效→资产对照 / 第 0 天清单 / 每轮闭环。**
  **落一个新任务时先读它**——资产之间本来互不引用，没有索引等于没有资产。
- `agents/long-horizon-auditor/AGENT.md` — 独立审计者角色定义（`bash install.sh` 会把它装成
  `<目标目录>/agents/long-horizon-auditor.md`，供 Task/agent 调用）
>
> **三个工具的共同纪律**：写工具本身也会犯本规程要防的错。
> `probe_liveness.sh` 第一版有四个自身缺陷（其中两个直接导致漏报/误报）；
> `claims_lint.py` 第一版有一个更隐蔽的：**用 TAB 当字段分隔符**——
> TAB 属于 IFS 空白字符，`read` 会把**相邻的多个 TAB 当成一个分隔符**，
> 于是**空字段被静默吞掉、整行错位一列**（"证据路径"读成了 `derived_from`）。
> 两处都是**只有拿已知答案的样本跑才被发现**的。
> ⇒ **给装置写脚本时，验收样本不是可选项。**

### 外部成熟方案（§2.5.2 三条结构的出处，2026-09-13 查证）

| 借的东西 | 出处 | 借的是什么 |
|---|---|---|
| **依赖网络 / justification** | **TMS（Truth Maintenance System）/ 理由维护系统**，Doyle 1979；de Kleer 的 **ATMS** 1986 | base fact 与 derived fact 分离；**结论带 justification**；前提被推翻时**沿依赖边传播撤回**（dependency-directed backtracking） |
| **双时间轴 / 失效而非删除** | 时序知识图谱的生物时间模型，如 **Zep / Graphiti**（arXiv 2501.13956） | **valid time 与 transaction time 分离**；"old facts are **invalidated — not deleted**"；每条派生事实可追回产生它的原始输入 |
| **取代语义** | **ADR / MADR**（Architecture Decision Records） | 状态取值 **`superseded by ADR-0123`**——是**指向新记录的引用**，**旧记录不编辑** |
| （旁证）溯源模型 | **W3C PROV**（Entity / Activity / Agent；`wasDerivedFrom` / `wasGeneratedBy` / `wasInvalidatedBy`） | 溯源信息的用途被明确写成"**对数据的质量、可靠性或可信度作出评估**" |
| （旁证）预注册 | 实验科学的 **Registered Reports** 制度 | 预测写在测量之前，约束的是"事后改口" |

> **一条边界**：以上方案给的是**记什么**，不是"自动帮你记"。TMS 要求 reasoner 显式产出 justification，
> 而 LLM 的推理不产生这种结构 ⇒ **没有可直接调用的自动实现**。
> 落地形式只能是 **约定 + 人工登记 + 可机械判定的 lint**（§2.5.1）。

> **一句话**：长程攻坚中，**最大的风险不是失败，而是"在错误的框架里持续成功"**；
> 紧随其后的，是**"在一次根本没跑过的实验上，成功地得出了一份看起来很专业的结论"**。
> 本规程的每一条，都是为了在还来得及的时候，逼出那句"我可能一直在错的地方努力"。
