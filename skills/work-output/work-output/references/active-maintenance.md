# 主动维护与发布提案

## 维护节点

- 每个检查点：更新 OUTPUTS.md / EPISODES.md 的状态，不改旧结论。
- 里程碑：验收通过、开源完成、数据集积累满 N 份，触发一次候选审查。
- 定期：每周或每月审查一次公开轨，把成熟候选升级为提案。

## 发布提案格式

```markdown
## 发布提案
- 产出：<文件/仓库/文章链接>
- 理由：<传播价值、时效性、完整度，至少一条>
- 时机：趁热发布 / 凑批发布 / 延后
- 风险：<隐私、夸大、维护负担>
- 需要你批准：是/否
```

## 规则

- agent 主动提出，但绝不自行发布；用户说“发布”才算授权。
- 同一产出不重复提案；被否后写原因，不纠缠。
- 发布后回填状态与 URL，并更新对应 episode 的 training_usage。
- 长期未成熟的候选标记“不发”并写明原因，避免积压噪音。
