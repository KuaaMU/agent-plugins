# 分层简报

## 三层结构

```markdown
## 一句话
<结论，含关键数字或结果>

## 五行
- 问题：<这个任务在解决什么问题>
- 决策：<选了什么方案，为什么>
- 证据：<哪条命令/数据/文件证明了它>
- 风险：<现在已知的边界或未验证项>
- 下一步：<下一个检查点或待确认问题>

## 附录
- 复现：<命令>
- 输出：<关键输出或文件路径>
- 失败记录：<如有>
```

## 写作规则

- 一句话必须能单独成立，不依赖对话上下文。
- 五行每行一句话，不是五行废话；没有风险就写“暂无”。
- 附录是给深挖的人看的，可以长，但主文保持精简。
- 用户负责项目时只需要读“一句话 + 五行”；附录用来追问和审计。

## 示例

```markdown
## 一句话
求解器在 10 张实拍图上平均 1.2 秒完成，全部满足 95% 填充率验收线。

## 五行
- 问题：实拍碎片在旧版求解器上偶发假解。
- 决策：改为缓存局部边缘刚性变换，保留 15 秒预算。
- 证据：regression_video.py 输出 10/10 通过，benchmark_summary.json 已存档。
- 风险：机械端吸嘴偏差未纳入测试。
- 下一步：真实机械动作联调后重新验收。

## 附录
- 复现：python tools/regression_video.py --data data/real
- 输出：benchmark_summary.json
```
