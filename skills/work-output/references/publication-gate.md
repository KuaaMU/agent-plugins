# 发布闸门

## 四项检查

### 1. 脱敏

- 全文搜索密钥、Token、口令、IP、MAC、串口号、设备路径。
- 删除或替换为占位符；检查日志和命令历史，不只检查正文。
- 不发布第三方个人隐私信息。

### 2. 许可

- 仓库已有 LICENSE 就沿用；没有则默认 MIT。
- 文本/数据类产出用 CC-BY 并注明。
- 明确声明“可用于模型训练”，否则默认不允许。
- 不发布你没有权利的素材。

### 3. 可复现

- 命令在干净环境重跑通过。
- 记录工具版本、依赖版本、数据集来源。
- 结果描述与证据一致，不夸大。

### 4. 质量

- 每项目最多一篇主案例 + 一个可复用资产。
- 标题和描述准确，不蹭热点式夸大。
- 发布后把 URL 和日期回填 OUTPUTS.md。

### 5. 用户批准

- 发布必须来自用户显式同意，agent 只能提出提案，不能自行发布。
- 提案写清链接、理由、时机、风险；用户说“发布”才算授权。
- 涉及模型训练授权时，单独确认，不能默认允许。

### 案例/文章与数据集额外检查

- 文章：陌生人能看懂；有标题、摘要、证据链接；平台与发布渠道已确定。
- 数据集：每份 episode 都有训练授权声明；批量脱敏复查；README 写明用途与许可证。

## 判定

全部通过 → 进入发布提案，等用户批准后发布。任一不通过 → 修复后重新检查，或标记“不发”。

## 维护

- 已发布资产若发现错误，发布更正而不是悄悄改。
- 旧案例过时后标注 archived，保留历史。
