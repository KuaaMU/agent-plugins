# 蒸馏规则

## 什么时候写

- 每个检查点通过或失败后。
- 连续 3 个思路失败，决定换路径时。
- 切换工具或模型前。
- 交付给用户前。

## 怎么写

### 新事实（进 TRUTH.md）

一行可验证陈述 + 来源 + 版本/日期 + 核对时间。不写解释性长文。

### 新经验（进 LEARN.md）

格式固定：`下次遇到 X，先试 Y，因为证据是 Z。`

- 好：`下次遇到串口重枚举丢字节，先按 bytes_written==0 只自动重发一次，因为实测重发多次会重复执行。`
- 差：`注意串口问题。`

### 公开候选（进 OUTPUTS.md）

标题 + 目标读者 + 状态（草稿/可发布/不发）。状态为“可发布”时才进入发布闸门。

## 去重与更新

- 写入前先搜索 LEARN.md/OUTPUTS.md 是否已有同类条目。
- 重复条目合并，旧条目标记 superseded 并指向新条目。
- 每轮只加真变化；没有新教训就写“无”，不硬凑。
