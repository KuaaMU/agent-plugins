# 验收清单模板

## 问题分级

| 级别 | 含义 | 示例 |
| --- | --- | --- |
| P0 | 阻断交付 | 结果错误、违反验收标准、真实环境不可运行、安全/数据破坏 |
| P1 | 严重缺口 | 边界情况失败、性能未达标、关键证据缺失或不可复现 |
| P2 | 可改进 | 命名、结构、文档、冗余 |

判定规则：存在任一 P0/P1 则不通过；只有 P2 可判通过但需记录。

## 验收流程

1. Reviewer 独立读取交付物、出口标准和证据位置。
2. 复现关键证据（命令、日志、数据），不信任摘要。
3. 输出问题列表：每条含级别、现象、复现方式、建议最短修复。
4. 写 REVIEW.md：结论、证据清单、未解决风险。

## 可定制检查清单模板

| 检查项 | 通过标准 | 证据 | 状态 |
| --- | --- | --- | --- |
| 功能正确 | 关键用例与期望一致 | 日志/数据/截图 | 待查/通过/不通过 |
| 验收标准 | 当前任务书逐条满足 | 对照表 | 待查/通过/不通过 |
| 真实环境 | 在目标环境运行成功 | 运行记录 | 待查/通过/不通过 |
| 可复现 | 同一命令可重复得到结果 | 命令+输出 | 待查/通过/不通过 |
| 回归 | 新实现不劣于基线 | 对比数据 | 待查/通过/不通过 |
| 安全边界 | 无不可逆/越权操作 | Guard 结论 | 待查/通过/不通过 |
| 证据存档 | 关键证据进入 REVIEW.md | 文件路径 | 待查/通过/不通过 |

## 写出口标准时的原则

- 可验证：用数字、路径、命令、截图定义“通过”，不用“差不多”。
- 随需求更新：每次检查点开始前重读当前任务书，出口标准以最新版为准。
- 分主次：优先正确性、可复现、真实环境；风格问题留给 P2。
